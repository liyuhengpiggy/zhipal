# 中文语音指令意图路由项目综合介绍

版本：hybrid-v2.3。整理日期：2026-10-25。

## 1. 项目定位

本项目解决语音交互链路中的模块选择问题：用户说出中文指令，手机先通过语音识别获得文字，再将文字发送到本服务。本服务判断应该调用摄像头文字提取模块、手机辅助操作模块，还是先向用户澄清。

本项目交付的是后端意图路由器。语音识别、摄像头图像采集、OCR 识别、Android 辅助功能执行以及多步任务编排需要由已有模块实现。服务只返回分类结果，不执行手机操作。

## 2. 输入、输出与能力边界

输入为一条非空中文文字指令，最多 200 字符。输出类别如下。一级结果为 `vision` 时，二级视觉任务继续区分为读取文字、识别物体和识别周围环境。

| 类别 | 含义 | 示例 |
| --- | --- | --- |
| vision | 读取摄像头前实体物品上的文字 | “把手里的票据上的字念出来” |
| phone_action | 打开应用、点击界面、设置提醒等手机操作 | “开启系统照相机”“把手机蓝牙关闭” |
| clarify | 指令不明确、取消、超出范围或跨模块组合任务 | “帮我处理一下这个”“不要打开微信” |

视觉二级类别为 `read_text`、`recognize_object`、`recognize_environment`。二级分类使用独立的 `vision_routes.json` 示例库和独立阈值/分差配置；明确表达由结构规则优先判断，未命中时使用 BGE 语义回退。二级分类不改变一级路由，非视觉请求的 `vision_task` 返回 `null`。

“打开相机”属于手机操作；“打开摄像头读取纸上的文字”属于视觉任务。当前 vision 限定为实体场景 OCR，读取手机屏幕、聊天窗口或应用截图中的文字按当前产品定义返回 clarify。

跨模块指令如“读取纸上号码后拨号”需要任务编排，当前版本期望返回 clarify。发送消息、输入文字和搜索时，应根据外层操作选择模块；正文中出现“不要”“识别文字”等词不应改变外层意图。

## 3. 技术方案

使用开源 Sentence Transformers 加载 BAAI/bge-small-zh-v1.5 中文句向量模型，结合自定义任务结构规则，使用 FastAPI 提供 HTTP 接口。

处理步骤为：输入校验 → BGE 编码与类别示例相似度计算 → 任务结构规则优先判断 → 未命中结构时使用语义回退 → 返回类别及诊断字段。

结构规则负责识别明确任务、否定和取消、跨模块操作、屏幕读字以及消息正文边界。语义回退计算输入与 routes.json 各类示例的余弦相似度，以每类最相近的示例作为该类得分。当澄清类最高、相似度不足或前两类差距过小时返回 clarify。

当前语义阈值为 0.45，最小分差为 0.06，保存在 router_config.json。它们使用单独的 60 条合成校准样本选择。本次改进没有训练或微调 BGE 权重；变化来自规则、示例和阈值。

当前实现为所有合法请求计算模型得分，之后应用结构优先级。即使结构已经明确，仍执行编码，以保持输出格式与诊断分数一致。因此规则命中不能理解成完全绕过模型的快速通道。

## 4. API 接入

默认地址：http://127.0.0.1:8010。接口文档位于 /docs，健康检查为 GET /health，分类接口为 POST /route。

请求示例：

```json
{"text":"帮我读一下摄像头前这张纸上的字"}
```

| 返回字段 | 说明 |
| --- | --- |
| route | vision、phone_action 或 clarify |
| needs_clarification | 是否需要澄清 |
| reason | 判断原因，例如 explicit_visual_text_task、small_margin |
| scores | 各类最近示例的余弦相似度，不是概率 |
| margin | 相似度最高与第二高类别的差值 |
| policy_version | 当前规则版本 hybrid-v2.3 |
| decision_source | structure 或 semantic |

结构规则可能覆盖模型最高分的类别，应以 route 为分发依据，结合 decision_source 和 reason 排查错误。调用方根据 route 将原始指令交给已有模块；手机操作模块仍需解析动作和参数。

默认仅监听电脑本机。手机接入需要将接口部署在现有后端或配置受控局域网访问，不能将电脑的 127.0.0.1 直接作为手机访问地址。

## 5. 部署与运行

当前环境为 Windows、Python 3.11.5、CPU 推理，server.py 使用 4 个推理线程。已验证的主要版本为 Torch 2.6.0、Sentence Transformers 3.4.1、Transformers 4.48.3、FastAPI 0.115.14、Uvicorn 0.34.3、httpx 0.28.1。

压缩包包含模型权重、分词器和配置文件，模型来源及哈希见 model-manifest.json。为保持可迁移性，压缩包不包含原机器的 .venv、缓存、运行日志及 PID。新机器仍需安装 Python 和依赖；安装依赖需要可用的软件源，或另外准备对应平台的离线 wheel 包。模型文件齐全后，server.py 可离线推理。

解压后在项目目录执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe server.py
```

requirements.lock.txt 记录原环境的完整精确版本，跨平台或不同 Python 版本不保证完全可用。requirements.txt 是较宽松的主要运行依赖范围，若使用它安装，应重新执行测试；API 测试和评估还需要 httpx。

Windows 后台运行可执行：

```powershell
.\start-service.ps1
```

该脚本隐藏窗口启动服务，已存在就绪服务时不会重启，不注册开机启动。修改代码、路由示例或配置后需重启进程。

## 6. 实验与测试结论

所有测试输入均明确标注为 synthetic，期望答案按任务定义预先生成，没有以模型预测充当标签。评估通过实际 HTTP 接口逐条调用。

| 数据与版本 | 正确数 / 总数 | 准确率 | 用途 |
| --- | ---: | ---: | --- |
| 原版 / 首批 2000 条 | 750 / 2000 | 37.50% | 初始基线 |
| hybrid-v2.1 / 首批 2000 条 | 1999 / 2000 | 99.95% | 已参与错误分析的回归集 |
| hybrid-v2.1 / 新增 120 条 | 117 / 120 | 97.50% | 首次验证后已查看错误，最终为复测 |
| hybrid-v2.1 / 全新 2000 条 | 1869 / 2000 | 93.45% | 新模板测试，本轮未根据结果调参 |

首批 2000 条复跑结果与上次一致。唯一错误是“帮我启动文件管理器”被保守判成 clarify。

全新 2000 条与此前测试、校准、验证及路由示例做了归一化去重：统一全半角和大小写、去除标点及空白后无重复。新模板覆盖实体读字、字段提取、口语、手机应用、设置、按钮、消息正文、媒体操作、取消、含糊表达、跨模块任务和屏幕读字。去重并不意味着语义独立。

全新测试分项结果：

| 类别 | 正确 / 总数 | 召回率 |
| --- | ---: | ---: |
| vision | 682 / 700 | 97.43% |
| phone_action | 659 / 700 | 94.14% |
| clarify | 528 / 600 | 88.00% |

全新测试共 131 条错误，其中 72 条应澄清指令被误分发到模块，占应澄清样本的 12.00%；主要问题集中在屏幕 OCR 和跨模块任务。另外，媒体操作、提醒等表达也存在误判。HTTP 错误为 0，本机顺序请求平均延迟约 9.0 ms，P95 约 10.6 ms，不包含语音识别、模型启动和模块执行时间，也不是并发吞吐指标。

15 项自动测试覆盖分数决策、否定、消息正文、混合任务、屏幕读字与按钮点击，以及真实模型 API 生命周期和输入校验。历史报告与源码快照均保留，方便复查。

不能将 99.95% 视为真实准确率：它来自参与优化的旧回归集。新集的 93.45% 更能揭示当前对新表达的不足，但同样来自合成模板，仍不能直接代表真实语音转写表现。

## 7. 复现命令

先启动服务，再执行：

```powershell
# 自动测试
.\.venv\Scripts\python.exe -X utf8 -m unittest -v test_router.py test_policy.py test_api.py

# 原 2000 条回归：输出到新的目录以保留历史结果
.\.venv\Scripts\python.exe -X utf8 evaluate_v2.py --output-dir evaluation\reproduce_original

# 全新 2000 条测试
.\.venv\Scripts\python.exe -X utf8 evaluate_v2.py --input evaluation\fresh_2000_20261025_015805\inputs_2000.jsonl --output-dir evaluation\reproduce_fresh
```

generate_dataset.py 是原始数据生成器，会写入原始数据文件；不要为复现评估而重跑它。新批次生成可使用 generate_fresh_dataset.py，每次创建独立目录并排除已有样本。calibrate.py 会改写阈值配置，复现当前已冻结结果时不应运行。

## 9. 当前限制与后续方向

结构规则只覆盖有限模式，复杂否定、指代、多步表达、陌生应用名称和 ASR 同音错字仍可能失败。语义相似度不是经过校准的分类概率，也不承担手机操作授权判断。

后续应收集并人工标注真实中文语音转写，冻结新的独立测试集；将已看过的新 2000 条作为错误分析数据，不能继续将其当作未见测试。优先检查屏幕文字能力边界、跨模块任务识别和消息正文范围，再比较专用分类器或监督微调方案。需要执行跨模块链路时，应另外实现任务拆分和调度。
