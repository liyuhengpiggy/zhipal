# 主 APK 真机验收与排错清单

以下是最终合并软件必须执行的运行验收，不是“已经全部通过”的声明。最终工程和目标手机尚未提供。记录表中的待验证项不能用本机编译成功替代。

## 1. 建议覆盖的设备/构建

| 环境 | 目的 | 状态 |
|---|---|---|
| 用户 HarmonyOS 4.2 / API 31 手机 | 既有运行目标，后台管理、悬浮和无障碍联动 | 最终合并 APK 待验证 |
| Android 13 / API 33 | 通知权限、拒绝后的状态 | 待验证 |
| Android 14 / API 34 | 投屏同意、FGS 类型和 token 单次使用 | 待验证 |
| 最终 targetSdk 对应的新系统 | 新平台行为兼容 | 宿主提高 targetSdk 后必测 |
| 主 APK debug 与 release/minify | 依赖、Manifest、反射/类名、资源合并 | 真实宿主待验证；交付另含构建示例记录 |

## 2. 首次安装

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 配置 | 冷启动主 APK | SDK 状态 configured=true，不依赖之前进程内残留配置 |
| 无障碍 | 打开系统设置启用新服务 | 系统开关与 SDK accessibilityConnected 均正确 |
| 拒绝授权 | 取消录屏授权 | 不显示“录屏成功”，不发模型请求，不点击 |
| 同意授权 | 再次申请并允许整个屏幕 | captureReady=true；无 SecurityException 或 IllegalStateException |
| 浮层拒绝 | 不给悬浮窗权限 | 明确提示授权，不崩溃、不把通知运行当成图标已显示 |
| 浮层同意 | 授权后启动 | 图标可见、可拖动、长按可关闭 |
| 通知 | 拒绝/授予 Android 13+ 通知 | 状态和引导合理，拒绝不被误报为无障碍失效 |

## 3. 正常预测与点击

1. 打开目标应用，点击 B。截图阶段允许短暂隐藏；模型等待时图标应恢复并显示省略号。
2. 模型结果直接显示悬浮面板。无需重新启动浮层服务才能看到结果。
3. 先按取消，确认目标应用没有发生点击；再测试待确认超时和返回/关闭回退 Activity。
4. 正常执行应只提交一次原生点击，或在系统明确拒绝后提交一次手势，不应成功后再补点。
5. “系统接受点击”只表示平台接受；必须观察业务页面是否完成预期任务。
6. 对比诊断中的截图毫秒、模型毫秒、请求次数和 native/gesture 方式。不要把服务端等待当成手机点击慢。

测试至少包括普通按钮、可点击父容器带子文本、列表同名按钮、动态时间/计数页面、原生点击不支持的自绘页面。无法读取控件树或系统禁止截图的页面允许明确失败，不能为了通过测试取消目标校验。

## 4. 取消、换页与任务抢占

- 待确认期间切换到不同应用：必须拒绝。
- 同一应用换到主要文字不同的新页：必须拒绝，不能只看包名相同。
- 目标禁用、删除、出现重复候选、明显移动、勾选状态改变：必须拒绝。
- 时钟或纯数字计数变化、树枚举顺序变化：不应仅因此取消未变化目标。
- 连续点击图标：不并发重复请求；有待确认结果时重新展示同一结果。
- A 开始前 await suspendForHostTask：B 的模型请求/待确认必须停止；A 结束后不执行旧建议。
- A 抛异常或取消：finally 中恢复 B，避免永久暂停。

## 5. 生命周期与录屏

- 系统停止投屏、锁屏导致投屏停止、另一会话接管：captureReady 应失效，不可复用旧 token。
- 旋转屏幕、改变分辨率：要求重新授权，不沿用旧尺寸点击。
- 划掉应用、系统杀进程、重新打开：模型配置重新初始化，旧 Bitmap/确认编号不恢复执行。
- 仅系统杀掉无障碍而图标仍在：点击图标提示重开无障碍；不能误报为模型无响应。
- 长按关闭图标后按 SDK stop：浮层和 SDK 本地投屏释放；用户无障碍开关仍由系统设置管理。
- 若共享宿主截图：host provider 就绪、停止、进程重建均能如实反馈；不能同时开两套投屏抢占。

华为/鸿蒙需实际检查“应用启动管理”的自启动、关联启动、后台活动等设置，界面名称可能随版本变化。前台服务和无障碍都不是绝对保活保证，代码不能替用户打开系统授权或阻止所有系统终止。

## 6. 常见错误定位

| 现象/错误 | 优先检查 |
|---|---|
| 系统找不到无障碍入口 | 最终 merged manifest 的 service、exported、BIND 权限、intent-filter、metadata 和 XML |
| 开关已开但未连接 | 等待系统连接；确认组件名是否升级改变；检查进程/系统后台策略 |
| 模型尚未配置 | Application 主进程是否每次启动 configure；不是只给示例 App 配了 Key |
| 403/400 | endpoint、模型 ID、账号权限、参数；不要通过重复录屏授权处理模型错误 |
| 模型等待 10–20 秒 | 复制诊断，查看模型耗时；服务排队/网络不由前端单方面保证 |
| MissingForegroundServiceTypeException | service 的 foregroundServiceType 和对应 uses-permission 是否被主工程删掉 |
| 录屏 SecurityException | 同意→FGS 提升→getMediaProjection 的顺序；是否重用 token 或多建 VirtualDisplay |
| ForegroundServiceStartNotAllowedException | 是否从后台无条件启动；推荐用户前台 Activity 操作 |
| 悬浮权限已申请但无图标 | canDrawOverlays 实际值；onStart 是否执行；是否被用户长按关闭；不要只看通知 |
| 预测时图标长时间消失 | 是否误混入旧版将图标隐藏覆盖整个模型请求的代码 |
| 结果需重开浮层才能看到 | 是否误混入旧版后台 Activity 弹窗路径；确认新版 FloatingPanelManager 在库中 |
| Duplicate class | 同时复制源码与引 AAR，或同时加载旧 MobileAgent/API 类；移除重复实现 |
| NoClassDefFoundError | 只复制单个 AAR，漏掉传递依赖/序列化/协程；优先完整 Maven 仓库接入 |
| release 独有崩溃 | 真正的 release/minify、consumer rules、Manifest 类名和依赖对齐 |
| 悬浮不影响模型但点击不生效 | 看 native/gesture、系统接受与页面变化；部分自绘控件并不保证支持 |
| A 结束后 B 一直暂停 | 主任务取消/异常后是否在 NonCancellable+Main 的 finally 恢复 |
| 设置页显示就绪但主工程用不了 | 检查 SDK 配置、服务连接、共享帧就绪分别是否真实；不要读历史 was_connected 偏好项 |

## 7. 设备测试脚本说明

完整源码 `tests/run-device-tests.ps1` 用于模块化示例，不是最终主 APK 的通用验收脚本。需设置 ANDROID_HOME、连接并授权设备、指定正确的 adb serial。新服务组件为 `com.bagent.sample/com.bagent.assistant.AssistantAccessService`；开启旧组件不算已开启新服务。

4 项设备测试包含权限页、兼容确认取消、直接浮层面板、真实原生控件单次点击。原生点击用例使用明确的假模型与假图片，但真实 Android View 和无障碍 ACTION_CLICK；不冒充云模型端到端测试。缺少无障碍/浮层权限会跳过相关用例，必须核查测试输出的跳过情况，不能只看 OK。
