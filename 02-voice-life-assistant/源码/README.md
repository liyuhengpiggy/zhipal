## 0.8.0：A 智能指令与一键权限修复

当前版本为 `0.8.0`（versionCode 21）。明确的打开应用、拨打已保存联系人、返回/桌面等操作继续优先使用 Android 本地能力；其他自然语言 A 指令可发送到团队自建代理的 `/v1/commands/interpret`，由服务端调用 Qwen3-VL 解析。模型只返回真实目录中的单步意图，手机在用户确认后重新检查任务、页面和控件再执行一次。第三方模型 Key 不写入 APK；手机设置中只填写团队代理地址和代理访问令牌。

## 0.7.9：交接服务接口与同音联系人确认

0.7.9 按队友的 APP_SERVER_HANDOFF 对齐交接服务：OCR 使用 `/api/v1/vision/tasks` 创建、原始 JPEG PUT 上传和状态查询；物体问答使用独立 `/api/v1/object-recognition`；B 沿用 `/v1/chat/completions`。交接服务共用根地址和服务器访问令牌，局域网 HTTP 仍只在调试包显式开启；硅基流动模型 Key 仅放服务端。

QQ、微信、抖音及其他有普通启动入口的应用都使用同一套名称查找流程，不需要每增加一个 App 就修改代码或录入包名。应用必须已安装、对助手可见且有可用启动入口；同名无法唯一确定时停止并说明，不猜选。设置页显示本机可启动应用数量和目录状态，原生联调页可先用文字测试。打开应用不需要逐个向目标 App 授权，也不需要开启无障碍权限；直接拨号仍需系统电话权限。

首次进入本版会显示“第一次使用 · 快速准备”，可一次集中申请蓝牙和直接拨号所需的基础权限；Android 11 及以下按系统要求申请位置权限以扫描 BLE。系统仍可能分别显示授权询问，必须由用户或家人确认，App 不能代点“允许”。引导可跳过，之后能在设置中重新打开；不要求开启无障碍、手机麦克风或通讯录权限。蓝牙开关、旧系统位置信息开关以及首次 ESP32 连接也在引导中说明。

老人首页保持视觉设计，不新增语音或拍照按钮。实际语音仍由硬件发送 WAV 触发，本机识别、执行与记录不依赖朋友的图片 `/analyze` 接口。浏览器中的模拟按钮始终只演示，不读取真实安装列表、拨号或打开应用。NextAction 保持独立、可选，普通打开应用和电话指令不经过 AI 单步补全。

朋友负责的视觉服务通过接口接入，可直接转发 [给视觉后端同学的接入清单](docs/给视觉后端同学的接入清单.md)。最小交付包括手机可访问的服务 URL、接口文档、真实成功 / 失败样例、鉴权规则，以及图片传输、拍照触发和结果回传方式。已有 `/analyze` 需要 `image + intent`，不能接收本流程 WAV，也不能充当文字事件存储接口；目前尚未完成真实图片问药闭环。

本版扩展的是“打开应用”，并未实现任意 App 内的发消息、视频通话、连续操作或账号多机同步。先保持手机解锁、助手在前台；**打开其他 App 后，回到助手再发送下一条指令**。目前没有锁屏、后台持续监听与跨 App 连续控制的保证。英文应用名、方言、噪声仍可能导致离线转写出错；需把转写错误与应用查找错误分开排查。0.6.2 构建、测试编译和 lint 已通过（0 错误、28 警告），80 项 JVM 测试全部通过，APK 版本及同证书 v2 签名已核验；具体见功能文档和 [交付校验](docs/0.6.2交付校验.md)。尚未连接真实 Android 手机或 ESP32，不把电脑测试当作真机全链路验收。

## 0.5.0 历史：首次验证顺序

1. 在 Android 8.0 或以上、支持通话的手机安装 App。保持解锁，并让助手在前台。
2. 先安装抖音完整版；当前包名为 `com.ss.android.ugc.aweme`，未适配极速版等其他版本。点“测试打开抖音”，应直接跳转。
3. 在 App 保存联系人，例如称呼“女儿”及一个可接听的测试号码，不读取系统通讯录。点“申请电话权限（只授权，不拨号）”，允许系统电话权限；此按钮本身不拨号。双卡手机可在系统中预先选默认通话 SIM。
4. 文字测试输入“给女儿打电话”，直接测试拨号。**会实际发起通话，可能产生费用。**保存称呼与说出的称呼必须一致，不用相似名字猜选号码。
5. 按固件提供的 Service / Notify / Write UUID 配置 BLE，搜索并连接，允许必要的“附近的设备”等系统权限。
6. ESP32 先发 `ping` 验证手机回 `pong`，再发 2–8 秒中文录音。推荐 16 kHz、单声道、16 bit 整数 PCM WAV，从 `RIFF` 文件头开始按顺序发完整文件字节。无需 JSON 或 Base64。
7. 看页面是否依次显示录音收齐、手机离线识别、识别文字和执行结果。说“打开抖音”或“给女儿打电话”分别验证；调试按钮只是辅助，不是日常使用入口。
8. 最后再接事件存储接口。地址暂时没有就留空，先在手机保存记录，不影响前面的语音流程。

必要权限只需在初次设置时按系统要求授权：BLE 需要附近设备；Android 11 及以下搜索 BLE 按系统要求需要定位权限和相关开关；实际拨号需要电话权限。打开抖音无需无障碍、悬浮窗或通讯录权限；识别 BLE WAV 不需要手机麦克风权限。单独的“手机麦克风调试”开关才使用系统识别服务及麦克风权限，该服务可能联网，与硬件 WAV 离线识别是两条不同路径。

## 0.5.0 历史：支持与限制

- 手机端支持“打开抖音”和“给已保存联系人打电话”等明确完整指令。不支持微信视频、发消息、任意控制其他 App；拍照问药仍由朋友的视觉链路负责，当前 APK 不包含完整问药闭环。
- 本地 WAV 解码支持整数 PCM（编码 1）、单/双声道、8–48 kHz、8/16/24/32 bit，内部转换为 16 kHz 单声道。单文件不超过 10 MiB，录音不超过 180 秒。推荐硬件直接录制 16 kHz 单声道 16 bit、2–8 秒短指令；压缩音频、浮点 WAV 和其他 WAV 编码不支持本地识别。
- 使用通用中文识别结果匹配完整指令，不把任意声音强制映射为电话或抖音。模型平均词分值需达到 0.65 才执行；分值未知或过低则显示“没有听清”，不执行。该分值不代表正确率，口音、噪声和称呼仍可能识别错误。
- 保留最近一段完整录音到 App 私有目录，可试听或手动重试；下一段替换上一段。手动重试会产生新事件，并可能再次拨号，页面已有文字提醒，不再多弹一次确认。
- JSON 事件按设备和事件编号保留最近 256 个去重；直接 WAV 没有硬件事件编号，每次完整重传都算新指令，不能自动去重。上一段正在识别时不要发送下一段。
- 必须在助手前台、手机解锁时测试。识别期间离开助手或断开/切换设备，迟到结果会记录但不执行。未实现锁屏、后台 BLE 保活或后台启动其他 App 的保证。
- “已请求拨打”仅表示已请求系统拨号，不表示接通；“已请求打开抖音”也不表示已完成抖音里的后续操作。设置中替换/删除联系人、手动打开联调报告仍保留相应对话框。

## 0.5.0 历史：后端分工

2026-10-23 已从开发电脑只读确认：`http://192.168.1.17:8000/health` 在线，`POST /analyze` 是图片接口，必填 `image` + `intent`。**继续供视觉功能使用，不要把它填为事件记录接口。**本版不向它发送 WAV，也不再要求朋友实现录音转写。

朋友提供单独的事件保存 URL 后，在 App“后端记录存储（可选，不参与识别）”填入；默认留空。手机把文字、执行结果等先写本机 SQLite outbox，再通过 JSON 异步同步。断网和接口失败不会卡住拨号、打开抖音；待同步记录保留在本机，前台会重试。服务必须在保存后返回 HTTP 2xx 及 `{"ok":true,"record_id":"与请求相同的编号"}`，手机才标为同步成功。

具体字段、BLE 消息和回传见 [接口约定](docs/接口约定.md)。当前尚未获得朋友真实的事件保存地址，不能声称已经存入他的数据库。账号登录、异地多机查看与完整历史页面也还需要后续实现；本版的本机记录不等于多机同步已经完成。

如需独立演示文字记录存储，项目有一个无第三方依赖的 Node 测试服务：

```powershell
node server/demo-server.mjs
```

它默认监听 8787，提供 `POST /v1/events`、`GET /v1/events` 及浏览器记录页，记录保存到 `server/data/events.jsonl`。手机与电脑连接可互通的 Wi-Fi/热点，在 App 填 `http://电脑局域网IP:8787/v1/events`。这只是测试存储服务，不是朋友现有 8000 端口服务，也不做语音或视觉识别。正式使用应接朋友实际的数据库和账户服务。
