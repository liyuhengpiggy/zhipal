# 0.7.1 功能与验证

日期：2026-10-24。目标手机华为 Mate30 5G / HarmonyOS 4.2.0，板端 ESP32-S3-Korvo-2 V3。此版本完成 Android OCR 客户端接入与电脑验证，服务部署和硬件真机联调待完成。

## 本次改动

- A 的读文字、药盒字段问题接入队友的异步 OCR 任务接口，B 保留原 Render 配置。新增独立 OCR 地址和令牌，默认空，不把旧 `/analyze` 误当新任务接口。
- 手机先建远端任务，再通过 BLE 请求本次拍照和原始 JPEG 上传；独立生成 vision_task_id，单图 f0，轮询约 240 秒。需要固件按补充协议适配。
- 设置页新增模型就绪检查、选择 JPEG 测试、按原编号查询上次任务、取消当前任务。断网保留原任务编号，查询时不重发照片。
- 检查任务编号、问题、帧编号、照片 SHA-256、候选证据和答案类型；手机选图还核对上传 bytes 的 hash。保留原文、核对提示、多候选和补拍提示。
- 新 A、配置修改、取消或断线关闭旧 OCR 请求，丢弃旧回调；A 优先及 B 清理规则继续适用。服务没有取消 API，远端旧计算可能继续，客户端会隔离结果。

原有本机打开应用、拨打已保存联系人、BLE 录音和离线 ASR 保留。一般实物提问继续旧的专属照片 URL 流程，能力需原后端另行验证。OCR 不提供通用物体识别、个人用药处方或手机自动点击；B 当前仍显示建议，由用户操作手机。

## 部署与实测边界

原 Render OpenAPI 在 2026-10-23 的只读检查中没有新 OCR API。此次没有修改线上后端。需按《发给后端同学_Render部署指令.md》部署独立服务，回传 HTTPS 根地址与令牌，再配置手机和板端。

本机没有队友服务所需的 Paddle Python 环境，未重新运行真实模型。原 ZIP 的 47 文件 manifest 校验已通过；原队友报告仅有两张合成日期图记录，并已提及布局排序误差。真实药盒需逐字核对生产日期/有效期、模糊与无标签、多候选和连续换图。不能凭 APK 编译或协议测试承诺 OCR 结果百分百正确。

部署服务 → 手机选 JPEG 独立验证 → 固件 JPEG PUT → 华为手机 A/B 抢占与断线验收，是后续联调顺序。服务和固件未准备好时，可使用既有 A 本机指令，OCR 会明确提示配置或请求错误。
