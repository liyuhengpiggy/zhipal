# 0.7.8 统一视觉任务接口：后端 / 固件交接

这是 APK 已实现的可选接口契约，**不是当前 Render 已部署成功的声明**。原服务的 `/upload`、`/analyze`、`/vision/analyze` 不能自动等同本接口。后端实现并验证以下契约后，手机再开启“使用统一视觉任务接口”；默认关闭以保留原通路。无需重训模型或在手机部署 OCR / Qwen 权重。

## 地址、鉴权和任务关联

- 手机填服务根地址，例如 `https://ai-glasses-backend-7bj3.onrender.com`，不要填 `/upload` 或 `/docs`。
- 创建和查询使用手机设置的自建服务 Bearer 令牌；留空仅适用于该服务明确允许匿名任务接口的情况。
- 第三方模型 API Key 只放后端。给 ESP32 的是仅能上传本任务 f0 的短期凭证，不是手机长期令牌。
- 手机每次新建唯一 `v_...` task_id；后端原样返回原问题、mode、task_id、expected_frames。不得拿“最近一张图”替代本次图。
- 后端支持 OCR、OBJECT、COMBINED 三种模式，均使用相同 API。APK 按问题中的文字/日期字段与物体特征词选模式，原问题保持不变；这是规则路由，并非语义大模型分类。

## 1. POST /api/v1/vision/tasks

请求 `Content-Type: application/json; charset=utf-8`：

```json
{
  "task_id": "v_demo_001",
  "question": "读文字并告诉我这是什么东西",
  "mode": "COMBINED",
  "expected_frames": 1
}
```

mode 大写。问题 1–1000 字；task_id 使用 APK 生成的值。同 ID 同参数重试应返回同任务；同 ID 不同参数返回 409。成功返回 200 或 201 JSON：

```json
{
  "task_id": "v_demo_001",
  "question": "读文字并告诉我这是什么东西",
  "mode": "COMBINED",
  "expected_frames": 1,
  "status": "awaiting_frame",
  "frame_id": "f0",
  "upload_method": "PUT",
  "upload_url": "https://your-service.example/api/v1/uploads/v_demo_001/f0",
  "upload_headers": {
    "X-Upload-Token": "仅本任务f0有效的短期上传令牌",
    "Content-Type": "image/jpeg"
  },
  "upload_expires_at": "2026-10-24T12:02:00Z",
  "mock": false,
  "inference_backend": "real"
}
```

域名、时间、令牌均为占位。过期时间必须为 ISO-8601 UTC，响应到达手机时还有 1–900 秒有效期，建议 120 秒，手机/服务器时钟需准确。新的创建响应必须 `awaiting_frame`，不得直接返回历史 succeeded。

upload_url 支持 HTTPS 签名 URL，或独立短期头凭证；不要发生 HTTP 跳转。仅调试包显式允许内网 HTTP 时，可用与任务服务相同的 HTTP 主机、端口。URL 最多 2048 字符，upload_headers 序列化最多 2048 字符，允许 `Authorization` / `X-Upload-Token` / `Content-Type`；不能把任务接口的长期 Bearer 直接放入头中转交眼镜。

## 2. ESP32 PUT upload_url

直接上传本次 JPEG 原始二进制，`Content-Type: image/jpeg`，附上 upload_headers；不是 multipart，不加 JSON/Base64 外壳。最多 8 MiB。

后端必须验证上传凭证绑定 task_id、f0、有效期和权限，校验完整 JPEG、存储不可变化的本任务文件、计算 SHA-256，再进入 queued / running。重复同内容应幂等，不同图覆盖同 frame_id 返回 409。上传成功返回 2xx，不要求手机读取上传响应 JSON。

服务端 OCR 模块产出可核对原文，物体模块按原问题回答，COMBINED 合并两者。模型未就绪返回真实失败，不输出演示模板冒充识别。

## 3. GET /api/v1/vision/tasks/{task_id}

所有响应必须包含相同的 task_id、question、mode、expected_frames，以及以下状态之一：

`awaiting_frame → queued → running → succeeded / failed / timed_out / expired`

awaiting_frame 可以跳过 queued 进入 running。APK 每约 1 秒查询，等待最多约 120 秒；网络单次连接 8 秒、读取 12 秒，整个 A 统一视觉流程另有 155 秒上限。取消、新 A、断线或配置变化会关闭请求并废弃本地旧回包；服务端仍应设置任务 TTL 清理旧任务，因为 APK 没有调用 DELETE。

成功示例：

```json
{
  "task_id": "v_demo_001",
  "question": "读文字并告诉我这是什么东西",
  "mode": "COMBINED",
  "expected_frames": 1,
  "status": "succeeded",
  "mock": false,
  "inference_backend": "real",
  "frames": [
    {"frame_id": "f0", "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"}
  ],
  "result": {
    "frame_id": "f0",
    "sha256": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
    "answer": "这是药盒；可见生产日期为……",
    "evidence_text": "本次照片真实识别的原文",
    "review_required": true
  }
}
```

示例中的哈希和答案不是实测结果。真实 sha256 必须是本次 JPEG 的 64 位小写十六进制。frames 只能包含本次 f0，result.frame_id / sha256 必须匹配；手机选图测试还会比对本地 JPEG 哈希。眼镜直传时 APK 校验服务器任务/图片记录的绑定，服务器必须保证上传绑定真实可信。

answer 必须非空且不超过 12000 字；OCR/COMBINED 的 evidence_text 必须非空且不超过 16000 字。看不清时 answer 明确要求重拍，不编造日期。review_required 对 OCR 默认 true，手机展示核对提示。OBJECT 可省略 evidence_text。

失败时保持任务关联字段，status 为 failed / timed_out / expired；HTTP 可使用 401/403（鉴权）、404（任务/接口不存在）、409（冲突）、413（过大）、429（忙）、503（模型/数据库未就绪）。APK 会停止并显示失败，拒绝显式 mock/demo 标志和不匹配任务。

## 4. 手机发给 ESP32 的 capture

BLE 为 UTF-8 换行 JSON，按既有 GATT 分片重组；手机字段在顶层：

```json
{
  "v": 2,
  "type": "capture",
  "source_button": "A",
  "session_id": "boot-001",
  "event_id": "rec-a-001",
  "task_id": "a-001",
  "vision_task_id": "v_demo_001",
  "frame_id": "f0",
  "mode": "COMBINED",
  "question": "读文字并告诉我这是什么东西",
  "upload_method": "PUT",
  "upload_url": "https://your-service.example/api/v1/uploads/v_demo_001/f0",
  "upload_headers": {"X-Upload-Token": "短期令牌", "Content-Type": "image/jpeg"},
  "upload_expires_at": "2026-10-24T12:02:00Z",
  "content_type": "image/jpeg"
}
```

task_id 是硬件 A 业务任务；vision_task_id 是服务端视觉任务，两者不能混用。只有来源带硬件元信息的录音才附 session_id；手机手动文字/选图测试没有硬件会话。

固件拍摄一次并 Wi-Fi 直传给 upload_url，成功后可通知：

```json
{"v":2,"type":"image_ready","id":"image-001","data":{"task_id":"a-001","vision_task_id":"v_demo_001","frame_id":"f0"}}
```

APK 仍按视觉 task_id 查询服务器终态，image_ready 不代表模型成功。不要把 JPEG 通过 BLE 回传，不要把手机截图当眼镜照片。固件收到取消或新 A 应停止旧任务；短期上传凭证不写串口公开日志。Wi-Fi、TLS、相机和固件端上传由硬件同学实现，本次 Android 改动不能替代这些工作。

## 最小验收顺序

1. 后端分别用真实 JPEG 跑通三种 mode，保留请求 ID、图片 SHA 和真实模型调用日志。
2. APK 设置中填根地址/自建令牌，在“服务器通路测试”选图，点“单独测试统一视觉任务”，核对真实结果弹窗；本测试不依赖开关，也不测试眼镜拍照或 TTS。
3. 后端与固件支持后打开统一视觉开关，硬件 A 语音分别询问文字/物体，观察 capture→Wi-Fi 上传→状态成功→手机弹窗和手机 TTS。
4. 断网、过期、旧 image_ready、A 抢占分别测试，旧图旧结果不能覆盖当前任务。
