核查日期：2026-10-24。对象：现有 Android 工程、0.7.9 调试 APK、队友交接材料及用户提供的软硬件技术说明。本次只核查和整理文档，未修改 APK 或重新构建。

## 1. 结论与当前可确认的范围

**调用千问 API、使用 Vosk/PaddleOCR、复用有许可的 MobileAgent-Android，并不会因为“用了别人的技术”就当然构成侵权或不能参赛。** 应把团队的设计与实现、第三方开源代码、第三方模型服务分别说明，并履行相应条款。

**存在功能相近的产品，也不能仅凭功能相似认定抄袭。** 穿戴式识读、图片问答、手机 GUI Agent 都已有公开产品或项目。需要进一步比较的是具体代码、文字、图片、界面表达、外壳设计以及有效专利的权利要求。自行实现同类功能也不等于完成了专利排查。

目前已找到主要开源组件和千问模型的许可依据，尚不能给出“全部提交权利已经确认”或“绝不侵犯任何第三方权利”的保证。主要未决事项是：赛事规则；基础 APK 与队友贡献的权属；硬件固件和外壳文件来源；当前服务端确切依赖；部分 APK 许可交付细节；实际 API 账户适用范围。

如果报名表要求勾选“团队有权提交本作品，作品内容不侵犯他人权利”，这是一项由参赛团队作出的事实承诺。本报告不能代替团队签署；也不应仅凭技术架构描述就视为已满足。确认第 7 节的事项后，团队才有更充分的依据作出声明。

## 3. 千问 API 具体意味着什么

按当前设计，涉及 Qwen 的实物问答与 B 屏幕理解路径为：手机或硬件提供经授权采集的信息 → 团队服务器/代理 → 硅基流动 API → `Qwen/Qwen3-VL-8B-Instruct` → 服务器返回答案/建议 → 手机显示、朗读；B 操作建议还需经用户确认后才允许执行一步操作。OCR 另走 PaddleOCR 任务接口。这描述的是调用架构，不代表代理部署、各条链路及整机闭环均已验收。

这属于集成第三方模型服务。APK 中未发现 Qwen 或 PaddleOCR 权重；手机确实打包了 Vosk 本地中文语音模型。**调用模型不使团队取得模型本身的版权，也不要求仅因这次 API 调用就把整个 APK 作为该模型的修改版本发布。** 自行部署或分发模型时，需另外核对确切权重及配套组件。

## 5. 当前交付中具体可修补的许可问题

这些是交付材料缺口，不能直接等同于已经发生侵权；本次没有修改已交付 APK。

1. **当前依赖版本表要更新。** `app/src/main/assets/licenses/b-agent/THIRD_PARTY_LICENSES/runtime-artifacts.json` 是导入时旧清单，其中 annotations 23.0.0、Kotlin stdlib 1.9.22 和 jdk7/8 1.9.10 不等于当前 APK 实际依赖。当前构建产物是 annotations 13.0、stdlib 2.0.21。
2. **单独列出 Public Suffix List。** OkHttp 的 `okhttp3/internal/publicsuffix/NOTICE` 和 `publicsuffixes.gz` 已实际保留在 APK 中，不能说原 NOTICE 丢失。但汇总清单把 OkHttp 只列为 Apache-2.0，且 `embedded_notices` 写成空数组。应补 MPL-2.0 说明、许可副本，并确认与当前二进制对应的源形式可由收件人及时获取。[MPL 2.0 第 3.1–3.3 节](https://www.mozilla.org/en-US/MPL/2.0/) 与 [官方 FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/) 已核：它允许与其他许可作品组合，不要求整个应用一律改成 MPL 开源。
3. **核 Vosk/JNA 的 native 子依赖。** `libvosk.so` 有 Kaldi/OpenBLAS 痕迹，`libjnidispatch.so` 有 libffi 痕迹；现说明只覆盖顶层。应按确切 AAR 构建来源核版本及版权/NOTICE，不能凭顶层许可替代所有子组件核查。
4. **清理旧说明。** 离线语音总说明标题仍为 0.5.0；B 许可 README 写有 `dependency-notices/` 目录，当前没有该目录。用户许可查看入口只覆盖语音说明与 Apache 文本，B MIT 已在 APK 内但未统一展示。建议下次构建统一为“开源组件与许可”入口，并附当前许可清单。
5. **更新 B 移植统计。** 上游清单 17 项和原导入哈希可追溯；现源码仅 10/17 项仍与记录上游字节一致，原文“12 个字节一致”为旧时状态。已有本地适配说明应随当前版本刷新。

当前 Apache 依赖主要以未修改二进制纳入。不能仅因调用库就判定缺少逐文件修改声明；若确实改过 Apache 组件源码，再按其第 4 节补显著修改说明及适用 NOTICE。
