# 0.5.0 手机安装与联调

这次按你的要求改为：硬件录音 → BLE 传 WAV → 手机离线转成文字 → 手机直接执行 → 文字和执行结果先保存在手机，有记录接口后再同步后端。

朋友原来的 `http://192.168.1.17:8000/analyze` 是图片分析接口。新版不把录音发给它，也不需要它帮忙转文字。

## 一、先把新版安装到手机

1. 电脑找到项目根目录的 `语音生活助手_0.5.0_安卓安装包.apk`。安装包约 83 MB，因为里面已经装了中文识别模型；Android 8.0 及以上可安装，建议预留 500 MB 可用空间。
2. 用微信“文件传输助手”把 APK 发送到自己的 Android 手机。微信不方便打开 APK 时，发送同目录的 `语音生活助手_0.5.0_微信传输备用.zip`，在手机“文件管理”中下载并解压，找到里面的 APK。
3. 在手机文件管理中点击 APK。首次安装时，按手机提示允许这个来源安装应用，然后安装。
4. 已装旧版时直接覆盖安装，联系人和设置会保留；不要先卸载。这个版本与之前本项目的安装包使用相同调试签名。如果系统提示签名冲突，先保留旧版和其中联系人，核对安装来源。
5. 打开“语音生活助手”，在页面靠下的“调试设置”确认版本是 `0.5.0`。

本包用于比赛 Demo 联调，未做应用商店发布。暂不需要登录账号。

## 二、只做一次的手机准备

1. 在助手中点“申请电话权限（只授权，不拨号）”，允许拨打电话。这一步只授权，不会拨出。
2. 在“联系人设置”输入称呼，例如 `女儿`，再填真实测试号码，点“保存联系人”。这些信息存于本 App，不读取手机通讯录。
3. 在手机中安装抖音完整版。当前打开的是包名 `com.ss.android.ugc.aweme` 的抖音，其他版本需另做适配。
4. 双卡手机在系统设置里选好“默认通话 SIM 卡”；没有默认卡时，系统可能要求选卡，这个界面由手机系统控制。
5. 联调时保持助手在前台、手机已解锁。每次打开抖音或拨号后，回到助手页面，再测试下一条。

Android 没有“一次开启二级权限就能控制所有 App”的通用开关。今天的两项功能只需要电话权限和连接硬件所需的蓝牙权限，不需要无障碍权限。手机品牌可能额外要求安全授权，App 不能代替用户跳过系统授权。

## 三、先单独验证电话和抖音

这样可以先确定手机操作是否正常，再排查录音。

1. 点“测试打开抖音”，应该直接请求打开抖音，不弹 App 的确认框。打开后回到助手。
2. 在测试文字框输入 `给女儿打电话`，点“测试这条文字指令”。它会查找你在本 App 保存的 `女儿`，直接实际呼出，不再问“确定拨打吗”。请使用准备好的测试号码。
3. 联系人称呼必须一致。例如保存 `女儿`，说 `给小丽打电话` 就找不到。可以把常用称呼分别保存为联系人。

日常硬件语音操作不需要点击这些测试按钮。它们只用于排查问题。

## 四、连接硬件并让 WAV 在手机转文字

1. 向硬件同学确认三个值：Service UUID、Notify UUID、Write UUID。在助手“设备连接设置”中填写。默认值是 Nordic UART 服务，不保证与你们固件一致。
2. 打开手机蓝牙，点“搜索附近 BLE 设备”，首次允许“附近的设备”。Android 8～11 扫描还可能需要定位权限及系统定位开关。
3. 找到开发板，点“连接”。界面应提示连接和订阅通知成功。
4. 在硬件麦克风旁用普通话说 `打开抖音`，录制约 2～8 秒。硬件停止录音后，先更新 WAV 文件头长度，再按顺序把整个 WAV 文件通过 Notify 发给手机。
5. 手机应自动显示“直接收到 WAV 文件”“录音接收完整”，随后准备模型、离线转文字，再显示“识别到：打开抖音”，并请求打开抖音。第一次收到录音时需解压内置模型，请等页面进度；不需要联网下载模型。
6. 回到助手，再测试 `给女儿打电话`。文字匹配成功且模型分值达到要求时直接呼出，不弹 App 确认框。

WAV 本身从 `RIFF` 开始按原始字节传输即可，不用封装 JSON，不用 Base64；每次 Notify 仍需遵守实际 BLE MTU。传输方式与 0.4.1/0.4.2 的直接 WAV 方式保持一致。下一段录音等上一段处理结束后再发。

推荐硬件输出 **16 kHz、16 bit、单声道、整数 PCM WAV**。本地转换还支持 8～48 kHz、1/2 声道、8/16/24/32 bit 整数 PCM；不支持压缩 WAV、浮点 WAV、MP3、AAC、M4A。每段最多 10 MiB、180 秒。改文件后缀不能改变录音编码。

## 五、不弹窗后怎么知道成功或失败

成功或已发出系统操作请求时手机短震一次；失败或没有听清时短震两次，并在页面写明原因。不播放语音。

识别失败不会自动弹窗，也不会自动反复拨号。“重新识别并执行上一段”是调试按钮：点击后会重新执行这段录音，可能再次呼出电话，没有额外确认框。平时无需点击。

只有联系人替换、删除，以及手动查看报告、开源许可等设置操作仍使用对话框。Android 首次权限、系统选卡等界面仍由系统控制。

| 页面情况 | 先做什么 |
|---|---|
| 没收到完整 WAV | 核对 UUID、Notify、MTU、WAV 文件头实际长度、是否丢包；不要把日志混进音频字节中 |
| “暂只支持整数 PCM WAV” | 让硬件同学改编码，推荐 16 kHz / 16 bit / 单声道整数 PCM |
| “没有识别出文字” | 点“试听上一段录音”，确认不是静音或杂音；靠近麦克风重录 |
| 显示的字不对 | 先看转写原文，放慢语速、用普通话、减少噪声。离线小模型会识别错，不会强行把近音词改成拨号指令 |
| “没有听清，未执行” | 模型平均分值不足 0.65，或没有可用分值；重说一次，不需点确认。这个分值不是准确率保证 |
| 转写对，但找不到联系人 | 核对本 App 保存的称呼，例如必须同为“女儿” |
| 文字测试也打不开或拨不出 | 查看电话权限、抖音安装状态、是否在前台，以及系统选卡/安全提示；先排除手机操作问题 |
| “识别期间离开页面或断开设备” | 本次文字会保存，但不执行过期指令；回到助手重新说一次 |
| 同步显示待配置、待上传 | 不影响本地识别和执行，按下一节对接记录接口 |

目前只保留最近一段完整录音，存在 App 私有存储中，新的替换旧的。文字记录独立存于本地数据库，断网可以积压后补传。手机麦克风测试开关与 BLE WAV 离线识别是两回事，默认保持关闭即可。

## 六、发给朋友的后端要求

可以直接复制这段：

> 0.5.0 的 WAV 识别和电话/抖音指令执行已经移到手机端，你不用接收或识别 WAV。请保留现有图片 `/analyze`，再提供一个保存事件 JSON 的接口，把完整地址和令牌告诉我。手机会分别发送转写记录 `audio_transcription` 和执行结果 `action_result`，通过同一个 `event_id` 关联。每条记录有唯一 `record_id`，请按它去重。保存成功请返回 HTTP 200/201 JSON：`{"ok":true,"record_id":"收到的相同编号"}`。完整字段见 `接口约定.md`。

朋友当前没有给出可用的记录接口。助手里的“记录存储接口完整地址”先留空，文字仍会保存在手机。不要把 `http://192.168.1.17:8000/analyze` 填进去，它是图片接口，不是事件保存接口。

等朋友真正实现接口后，填入实际地址、与他约定的设备编号、可选令牌，点“保存后端设置并同步记录”。成功会显示“记录已同步到后端”；手机网络不通时保留待上传记录。

项目的 `server/demo-server.mjs` 是另一份本地记录存储演示，不会修改朋友的服务器。若要先演示保存文字，可在装有 Node.js 的电脑项目目录执行 `node server/demo-server.mjs`，手机与电脑连接同一可互通网络；手机填写 `http://这台电脑的局域网IP:8787/v1/events`，电脑浏览器打开 `http://localhost:8787` 可查看记录。此演示没有账号系统，不能替代未来同账号多手机登录功能。

## 七、已验证和需要真机验证的部分

新版 APK 已完成编译、静态检查以及 BLE/WAV/文字处理的自动测试。相同中文模型还用 Windows 合成录音测试过“打开抖音”“给女儿打电话”和两条否定句；一款合成声音能通过，另一款曾把“抖音”识别为“口音”，未执行。

这些是开发机验证。本次没有连接 Android 手机和 ESP32，尚未确认你这部手机的原生模型加载、真实硬件收发与实际呼出结果。按上面的顺序测试，遇到问题点“查看 / 复制本次联调报告”，报告会显示录音、转写、权限、同步和操作阶段，便于继续定位。
