## 0.7.4 修正

模型候选动作从提供图片坐标改为选择当前截图控件列表的 `target_id`：

```text
### Thought ###
选择控件的理由
### Action ###
{"action":"click","target_id":17}
### Description ###
点击该按钮，等待用户确认
```

候选控件编号来自本次无障碍控件检测，并与截图上的标注一致。只列出启用、可点击、有可读标签、非密码且通过敏感操作策略的控件。模型只能选择已有编号，手机将编号转换为该控件实际中心坐标；模型坐标完全不被接受，也不按名称模糊匹配。不存在的编号、重复字段、额外参数、多个动作、字符串编号、浮点编号都会被拒绝。

用户仍须在具体动作提示后再次按 B 明确确认，才会重新截图核对窗口、页面与控件并执行一次。模型说“已经确认”没有执行权限。A 开始到达手机时仍会取消 B 请求、提示和旧任务，不恢复旧 B。

0.7.4 本地 122 项 JVM 测试通过，包含新增控件编号解析、非法编号、重复字段、额外坐标拒绝测试；调试/正式构建通过，Lint 为 0 errors / 33 warnings。调试签名延续原版本，正式构建仍未签名且只允许 HTTPS。

充值后模型已实际返回正确的控件编号，并通过解析校验；双图相同截图的无变化分支也已通过。此前的失败输出保留在本地 `tmp/b-agent-live-response/` 便于核对；不是模型成功案例，也不包含 Key。

代理部署步骤继续参考 [0.7.3 Render 配置](B_Agent_硅基流动接入_0.7.3.md)，固定上游和模型不变。`SILICONFLOW_API_KEY` 仅放 Render 环境变量；手机填写不同的 `B_PROXY_TOKEN` 和实际部署的代理 `/v1` 地址。安装 0.7.4 后无需把硅基流动 Key 写入手机。

充值后的规划、控件编号候选和双图无变化检查现已通过，真机流程仍待验证。`scripts/b-model-live.mjs` 可复用 APK 同一套请求构造和解析器，测试前需编译 `:app:compileDebugUnitTestKotlin`，并通过 `SILICONFLOW_API_KEY` 环境变量或受控标准输入提供 Key：

```text

```

当前脚本专用于此历史截图，控件编号与位置是人工转录的测试夹具，不能替代真实手机无障碍控件树。双图阶段会发送两份相同图片，预期结果 C，验证无可见变化时不会冒称成功；需要补充真实前后两图才能验证有变化的操作结果。脚本只生成模型请求并解析，不连接无障碍服务，不会点击。
