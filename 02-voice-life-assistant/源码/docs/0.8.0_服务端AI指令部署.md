# 0.8.0 服务端 AI 指令部署交接

这次更新的是 `b_agent_proxy` 自有云端代理，不训练或部署模型权重。A 用 ASR 文字解析一个意图，B 发送手机截图获取帮助建议；两条接口独立校验，模型均固定为 `Qwen/Qwen3-VL-8B-Instruct`。本地测试通过仅说明代码可运行，不代表 Render 已部署或真实模型已就绪。

## 后端同学执行

1. 将 `b_agent_proxy` 目录更新到现有代理的代码仓库。必须包含 `server.mjs`、新增 `command.mjs`、`package.json`、`test.mjs`、`command.test.mjs`、`.env.example` 和 `README.md`。勿上传真实 `.env`、密钥或截图日志。
2. Render 继续使用原 Web Service，Root Directory 指向该目录，选择 Node 24 LTS；Build Command 为 `npm install --ignore-scripts && npm test`，Start Command 为 `npm start`，Health Check Path 为 `/healthz`。无需 npm 第三方依赖。
3. 仅在 Render 环境变量中设置 `SILICONFLOW_API_KEY` 为真实硅基流动 API Key，`B_PROXY_TOKEN` 为另一段随机访问令牌（至少 32 字符、不可使用第三方 Key）。保留 Render 自动注入的 `PORT`。第三方 Key 不写入源码、APK、手机设置或交接文件。
4. 提交代码后在 Render 执行部署。构建、自动测试和健康检查通过后，再执行以下验收。保留已有 B 代理 URL 与访问令牌可减少手机重新配置；若换了地址或令牌，单独通知 APK 同学。

## 接口与手机配置

| 用途 | 接口 | 输入/输出 |
|---|---|---|
| A 自然语言 | `POST /v1/commands/interpret` | 纯文字原问题、task_id、真实应用/联系人/控件目录 → 单个 JSON intent |
| B 页面帮助 | `POST /v1/chat/completions` | JPEG Base64 截图与页面上下文 → 保持现有 B 响应格式 |
| 健康检查 | `GET /healthz` | 无需令牌；返回两条能力声明，不证明上游额度或模型调用成功 |

两个 POST 均使用 `Authorization: Bearer <B_PROXY_TOKEN>`、`Content-Type: application/json`。在 APK 的 A 云端设置填写该代理 HTTPS 根地址与代理令牌；B 保持其独立截图设置。原先视觉 OCR `/upload` 服务不等于本代理，不能据此替换 A AI 地址。

A 请求示例（下列应用、联系人和页面仅是协议示意；联调时使用手机真实目录）：

```json
{"version":1,"task_id":"a-demo-001","utterance":"打开微信","apps":[{"id":"com.tencent.mm","label":"微信"}],"contacts":[],"screen":null}
```

成功响应示例：

```json
{"version":1,"task_id":"a-demo-001","intent":{"type":"open_app","target":"com.tencent.mm"}}
```

目录上限为 500 应用、100 联系人、80 控件；正文不超过 128 KiB；原问题最多 2000 字符且不含控制或格式字符（包括换行），A 上游超时约 18 秒。未知 ID、越权动作和非法模型输出被拒绝。关闭指定应用只允许与当前 `screen.package_name` 一致，否则返回澄清；其他自然语言的返回、退出、跳转由模型理解，无须逐句添加固定口令，含义不清则询问。退出只表示返回桌面，不能强行停止后台进程。代理不控制手机；用户确认、旧任务失效和执行后停止由 APK 负责。

## 固件配合：A 语音应答关联

APK 在询问操作确认、同音联系人或澄清时通过 BLE 下发 `type=a_clarification`、`source_button=A`、`task_id`、唯一 `prompt_id` 和 `question`。用户随后按 A 回答时，固件在该次 `button_start` / `audio_start` 的录音元数据中原样回传这个 `prompt_id`，保留 A 的 `purpose=command`、本次独立 `task_id`、`event_id`、`session_id`。`prompt_id` 仅接受 1–96 位 ASCII 字母、数字及 `._:-`。

APK 仅将匹配且未过期的问题关联到本次回答；新指令、断线、取消、超时均清除旧建议。未回传或编号不同的录音不能批准旧操作。旧固件、裸 WAV 和 v1 文字帧可继续发送完整 A 指令，确认请点击手机弹窗；目前未验证真实固件的回传支持。

## 发布前必须留证

- 构建测试全部通过；部署后的 `/healthz` 包含 `capabilities.a_command_interpreter.path=/v1/commands/interpret` 和 `b_agent_chat=true`。
- 使用代理令牌实际请求一次 A，记录 HTTP 状态、耗时、task_id 和 intent，确认确实调用硅基流动且没有虚构目标；再由真实手机验证启动应用。
- 使用真实截图实际请求一次 B，确认 B 解析成功，并在手机验证未确认不执行、拒绝不执行、A 启动后旧 B 建议失效。
- 验证缺少/错误令牌返回 401，错误输入返回 400，模型失败返回 502；网络失败在手机显示失败且可重试。日志只记录状态、耗时和任务编号，不记录密钥、截图、联系人或完整语音。
