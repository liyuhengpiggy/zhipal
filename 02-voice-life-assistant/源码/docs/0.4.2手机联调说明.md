# 0.4.2 手机联调说明

> **历史文档：仅适用于 0.4.2，请勿按本文配置 0.5.0。** 0.5.0 已改为手机内置中文离线识别：BLE WAV → 手机转文字 → 手机执行 → 可选后端保存文字记录，不再上传 WAV，也不需要后端新增语音识别接口。日常拨号、打开抖音、重试及识别失败不再弹出 App 二次确认。当前步骤请看 [0.5.0 手机安装与联调](0.5.0手机安装与联调.md) 和 [接口约定](接口约定.md)。以下内容保留用于解释旧版问题。

## 先说清楚这次卡在哪里

当前方案是：ESP32 录音 → BLE 发送 WAV → App 收齐录音 → 上传后端 → **后端把声音识别成文字** → App 根据文字执行电话或抖音 → 手机显示文字并震动。

“WAV 收到”只证明蓝牙文件接收完成。“开始上传 / 请求写出”也不证明后端已经接收并识别成功。只有后端返回真实转写文字（例如 `transcript: 打开抖音`）后，App 才能匹配指令。

2026-10-23 已在开发电脑只读检查你提供的服务器：

- `GET http://192.168.1.17:8000/health` 返回 `{"status":"ok"}`。
- `/openapi.json` 声明 `/analyze` 是 **Analyze Uploaded Image**。
- 必填文件字段是 `image`，另一个必填文字字段是 `intent`。
- 返回的是 `action/app_name/target/confirmation_required/message`，没有 `transcript`。

结论：服务在线，但现有图片接口和 App 的录音识别协议不匹配。App 当前没有内置 WAV 识别模型；后端的图片 AI 也不等于具备语音转文字能力。没有读取手机当时的 HTTP 响应，不能确定当时具体报错码。新版会把该响应直接显示出来。

## 把新版装到手机

1. 将 `语音生活助手_0.4.2_安卓安装包.apk` 发到自己的微信或通过 USB 传到安卓手机。
2. 微信不让安装时，先保存文件，再在手机“文件管理 / 下载”找到 APK 打开。若 APK 被拦，可传备用 ZIP，在文件管理中解压再打开 APK；不要直接把 ZIP 后缀改成 APK。
3. 系统询问时，允许这次使用的文件管理器安装应用。选择更新安装，先不要卸载旧版；同一签名更新可保留联系人和已保存设置。
4. 打开“语音生活助手”，看到版本 0.4.2。保持手机解锁，助手在前台测试。

## 第一步：不接蓝牙、不用后端，先验证手机操作

这一步只是测试入口。正常使用仍然由硬件语音自动触发，不需要点击这些测试按钮。

1. 手机先安装抖音**完整版**。当前代码使用包名 `com.ss.android.ugc.aweme`，未适配抖音极速版等其他应用。
2. 在“手机操作检查”点“测试打开抖音”。应跳转抖音；然后回到助手。若显示未安装，检查安装的是不是完整版。
3. 在“联系人设置”保存称呼，例如“女儿”，号码填写本人或同伴可接听的测试号码。不会读取系统通讯录。
4. 点“申请电话权限（只授权，不拨号）”，系统提示时选择允许。此按钮本身不会打电话。
5. 在文字测试框输入“给女儿打电话”，点“测试这条文字指令”，核对确认框内号码，再点击拨打。**这会实际发起电话，可能产生通话费用。**
6. 若此前永久拒绝权限，点“打开本 App 系统权限设置”，在权限里允许电话，再回助手。上方应显示“电话权限：已允许”。

这两项通过，说明本机指令执行路径可用。后续录音识别失败应继续查上传和后端，而不是反复开启其他权限。

| 功能 | 需要什么 |
|---|---|
| 接收 ESP32 BLE | 搜索时允许“附近的设备”；Android 11 及以下按系统要求允许定位并开启相关开关 |
| 实际拨打普通电话 | 电话权限、已保存且称呼一致的号码、支持通话的手机及可用通信服务 |
| 打开抖音 | 安装抖音完整版；这一步不需要无障碍、悬浮窗或通讯录权限 |
| WAV 上传后端 | 手机可访问后端网络，正确 URL/字段；联网权限已在 App 声明，无需逐次弹窗开启 |
| 手机震动 | 已声明震动权限；震动效果受手机硬件和系统设置影响 |
| 临时手机麦克风调试 | 仅打开相应开关时需要麦克风权限和手机上的识别服务；这不负责识别 BLE 文件 |

当前“控制手机”只实现了上面两种动作；不包含微信视频通话、微信发消息、任意操作其他 App，也没有锁屏/后台自动操作保证。系统可能选择 SIM 卡或进一步确认；“已请求拨打”不等于对方已接通。

## 第二步：让后端同学补齐真正的录音识别接口

可以把下面这一段原样发给朋友（本文不会自动发送消息）：

> 我们的手机已通过 BLE 收到完整 WAV。现在 POST `/analyze` 的文档要求 `image` 和 `intent`，是图片接口。请另外提供录音转文字接口，真实识别上传的 WAV；告诉我完整 URL、文件字段名、是否需要 Token、支持的 WAV 编码。App 用 multipart/form-data 发送 `audio` 文件（字段可配置）以及 `device_id`、`event_id` 文本。请同步返回 HTTP 200 JSON：`{"ok":true,"transcript":"打开抖音","reply":"识别成功"}`。transcript 必须来自这段录音，不能写死；没识别出来应返回失败，不要返回猜测指令。现有图片接口保持供视觉功能使用。

建议音频：WAV、单声道、16 kHz、16 bit PCM，包含完整 WAV 文件头；实际以识别服务支持的编码为准。后端自行选择并配置可用的 ASR 引擎/服务、密钥及音频解码。单纯把文件存数据库不会生成文字；图片分析模型不一定支持音频。

例如朋友可以新增 `/transcribe`，但这只是建议名称，当前服务器没有发现这个接口。**要等后端实际实现，不能现在只改地址就期待识别成功。**

最小约定：

```text
POST http://<后端电脑IP>:8000/<真正的录音识别路径>
Content-Type: multipart/form-data; boundary=<客户端生成>

audio: recording.wav 的真实文件内容
device_id: elder-xxxx
event_id: wav-唯一编号
```

```json
{"ok":true,"transcript":"给女儿打电话","reply":""}
```

`reply` 可省略。也接受 `text` 代替 `transcript`，以及 `data` / `result` 对象内的这两个字段。只有 `answer` / `message` / `action` 的图片分析响应不算语音转写，不会直接执行。HTTP 202 仅排队还不支持，需要后端同步返回识别结果。

后端应先用自己电脑上的真实 WAV 验证：能收到文件、能解码、能真实转写、返回格式正确。之后告诉 App 同学准确地址。后端监听 `0.0.0.0:8000`，允许局域网连接；手机能访问该 IP，端口未被防火墙阻拦。数据库记录及图片分析可以继续使用各自独立接口。

## 第三步：完整联调

1. 手机连接能访问后端电脑的 Wi-Fi。浏览器打开健康地址；开发电脑能访问不代表手机一定能访问。
2. 在 App“后端连接设置”填朋友实际完成的录音识别 URL、文件字段（例如 `audio` 或 `file`）、设备编号。Token 未要求时留空。先点“保存后端设置并同步记录”。“事件记录接口”可以留空，不要把图片/录音接口填进去。
3. 点“检查已保存的后端接口”。如果仍显示 `image + intent` / 协议不匹配，说明还没切到真正的录音接口。检查是读取 OpenAPI 文档，不是识别测试；无文档也不代表接口必定不可用，需后端人工确认。
4. 按硬件同学提供的 UUID 搜索并连接 BLE，允许必要权限。硬件发送短录音，例如说“打开抖音”，发送完整 WAV 文件字节。
5. 首页应显示阶段：接收 → 连接 → 发送 → 等待响应 → HTTP 200 → 后端已返回识别文字。随后显示“识别到：打开抖音”，请求打开抖音并震动。
6. 分析失败时，弹窗会给出具体错误。可以点“复制内容”，或首页“查看 / 复制本次联调报告”，把报告自行发给朋友，不要只说“分析失败”。
7. 点“试听上一段录音”，调高手机媒体音量：是否有人声？是否只有噪音/静音？无法播放或声音异常要让硬件同学核对录音编码和数据完整性。
8. 朋友修正后端后，保存正确设置，再点“重新识别上一段录音”。会再次上传并可能再次执行电话/抖音，请确认录音内容；新录音会替换旧录音。App 不会后台自动反复拨号。
9. 测试电话时，把称呼与 App 保存的联系人完全对齐，例如保存“女儿”，说“给女儿打电话”。当前不会用相似称呼猜选联系人。

## 错误怎么看

| 看到的情况 | 优先检查 |
|---|---|
| 收不到完整 WAV / 接收超时 | BLE 通知、分包顺序、WAV 最终长度、连接中断，找硬件同学 |
| 无法连接 / 连接超时 | 手机 Wi-Fi、IP/端口、后端启动、监听地址、防火墙，双方共同检查 |
| HTTP 400 / 422，detail 提到 image/intent | 打到了图片接口，或表单字段未对齐；看后端接口文档 |
| HTTP 401 / 403 | Token 和后端鉴权 |
| HTTP 404 / 405 / 307 | URL、方法、结尾斜杠；填写最终 POST 地址 |
| HTTP 413 / 415 | 后端大小限制、支持格式、WAV 编码 |
| HTTP 500 / 502 / 503 / 504 | 后端识别服务、模型、密钥、解码器和后端日志 |
| 等待后端识别超时 | 后端推理或上游服务耗时、网络；请求可能已被接收，先查日志 |
| HTTP 200，但缺少 transcript/text | 返回协议错误，或后端只做了图片分析/文件存储，没有提供转写 |
| 识别文字正确，但没有执行 | 指令措辞是否支持、联系人是否保存、电话权限、抖音安装、助手是否在前台 |

## 本次验证范围

APK 的构建、静态检查、BLE 协议测试及本地 HTTP 协议测试由开发电脑验证。已只读检查真实后端文档与健康接口；没有从这里修改朋友的服务器、调用真实 ASR 或远程拨打你的电话。未接入真实安卓手机和 ESP32，完整真机结果须按上面的步骤验证。

本次结果：构建和 lint 通过，JUnit 31 项测试通过（BLE 19 项 + HTTP/识别响应/指令 12 项），APK 签名验证通过且与旧版一致。没有把测试服务器的固定转写结果当作真实语音识别成功。
