语音生活助手 0.6.2 · 完整交互测试版使用说明

一、先分清两个文件

1. 语音生活助手_0.6.2_安卓安装包.apk
   安装到 Android 手机的真实测试软件。视觉设计已经放进同一个 App 首页，不需要另外启动浏览器。
   本版保留 BLE 接收完整 WAV、手机本地 Vosk 离线转文字、拨打 App 内联系人、本机记录及可选后端同步；打开软件改为按手机里的真实应用名称查找，不再只能打开抖音。
   同时保留独立、可选的 NextAction 安全练习，普通语音打开 App 和拨号不需要开启它。

2. voice-life-demo.html
   电脑浏览器里的可点击视觉预览，用模拟数据展示页面和处理阶段。
   其中的演示按钮不会真的接收 WAV、识别录音、读取手机应用列表、拨号、打开软件、上传图片、发送定位或通知联系人。

老人首页不显示“语音控制”和“拍照问药”操作按钮。日常语音入口仍是硬件发来的录音，首页显示设备状态、处理阶段和最近结果。图片问药的真实传输与分析闭环尚未接入，不能因为页面能演示就当作已经完成。

二、发到手机并安装

1. 手机需要 Android 8.0 或以上。把 APK 发到手机安装；微信不能直接使用 APK 时，发送“语音生活助手_0.6.2_完整测试版.zip”。
2. 手机微信下载 ZIP，选择“用其他应用打开”，交给文件管理器解压，再点其中的 APK。ZIP 本身不能直接安装。
3. 系统若询问是否允许文件管理器安装应用，由本人或家人按系统步骤确认，再返回安装。
4. 已安装旧版就直接覆盖，不要先卸载。同签名覆盖通常保留联系人、设置及本机记录；卸载或清除数据会删除本机资料。
5. 确认安装的是 0.6.2。本包用于比赛联调，尚需在你的手机和 ESP32 上完成实际测试。

三、第一次进入：把基础权限集中准备好

1. 首次进入本版会显示“第一次使用 · 快速准备”。点“开启基础权限”，按 Android 系统提示确认：
   Android 12 及以上需要附近的设备权限；Android 11 及以下扫描 BLE 按系统要求需要位置权限。直接拨号需要电话权限。
2. 这一步只授权，不会立即拨号。系统可能分几次询问，必须由用户或家人自己点“允许”，App 不能代替确认，也不能自动开启全部特殊权限。
3. 若蓝牙未开，点“开启手机蓝牙”，再在系统提示中确认；旧系统如要求打开位置信息，按引导进入系统设置处理。
4. 可以点“完成并返回”，也能点“稍后设置，先进入软件”。之后在“设备与设置”点“基础权限与蓝牙设置”，或在原生联调设置点“首次使用 / 集中权限设置”，都能重新打开引导。
5. 拒绝权限不影响进入页面，但相应功能暂时不能使用。系统不再弹授权框时，通过引导中的系统设置入口自行开启。
6. 打开 QQ、微信、抖音等普通 App，不需要逐个授权“允许打开”，也不需要无障碍权限。硬件 WAV 识别不需要手机麦克风；联系人自己填在 App 内，不需要读系统通讯录。
7. 双卡手机可以由家人先在系统里选默认通话卡，减少日常选卡步骤。系统或厂商自己的提示无法由本 App 统一消除。

四、先不用硬件，测试手机能否执行

1. 保持手机解锁，让语音生活助手在前台。在“联系人”页保存称呼与测试号码，例如“女儿”。这里保存的是 App 自己的联系人。
2. 打开“设备与设置”，看“语音打开应用”里的本机可启动应用数量及目录状态，再点“打开原生联调设置”。
3. 用文字测试入口输入“打开 QQ”“启动微信”或“打开抖音”。这些例子需要手机已安装对应软件。
4. 软件会按真实的手机应用名称查找启动入口；以后安装其他普通 App，不需要你逐个录入包名。尽量说手机图标显示的名字。找不到、同名无法区分或读取目录失败时，会显示原因并停止。
5. 每打开一个其他 App，先返回语音生活助手，再测试下一条。本版没有后台、锁屏或跨 App 连续控制的保证；不在首页放按钮，不代表后台常驻功能已经完成。
6. 输入“给女儿打电话”。称呼要与保存的一致；电话权限已允许后会直接请求系统拨号，不再加 App 二次确认。会真实拨出，请使用可接听的测试号码。
7. “打开 QQ”只负责启动 QQ；本版尚未实现继续在 QQ / 微信里自动发消息、指定好友视频通话等操作。

五、连接 ESP32，测试真正的 WAV 语音

1. 在原生设备连接设置填写硬件同学提供的 BLE Service / Notify / Write UUID。默认值相同就不必改；搜索并连接自己的 ESP32。
2. 先发送 ping，确认手机回 pong。它只验证 BLE 消息互通，不代表录音识别已经通过。
3. 硬件按顺序发送完整 WAV 的全部文件字节，从 RIFF 文件头开始。推荐 16 kHz、单声道、16 bit 整数 PCM，2–8 秒一条；直接 WAV 不需要加 JSON 或 Base64。
4. 说“打开 QQ”“打开抖音”或“给女儿打电话”。真实流程是：
   ESP32 录音 → BLE 收齐 WAV → 手机离线转文字 → 查应用名称 / 查已存联系人 → 请求系统执行 → 本机存记录 → 可选后端同步。
5. 看页面依次显示录音收齐、离线转写完成、识别文字和操作结果。首次识别需要准备内置模型，请等待，不要连续发送多条录音。
6. 等上一条处理结束，并回到助手前台，再发下一条。识别途中离开页面、断开或切换设备，迟到结果可以保存，但不会补执行旧指令。
7. 反馈以页面文字和手机震动为主。已请求拨号不等于对方已经接通；已请求打开软件不代表软件内的后续任务完成。

六、朋友的后端怎么接

1. WAV 在手机本地识别，不发送给朋友的图片接口。
2. http://192.168.1.17:8000/analyze 是图片分析接口，需要 image 和 intent；它不是 WAV 转写接口，也不是事件记录接口。
3. 事件保存需要另一个真实 URL。朋友还没提供就留空，手机仍能识别、执行并保存本机记录。提供后再配置，手机异步上传文字和执行结果。
4. 朋友在另一台电脑开发没关系。把“docs/给视觉后端同学的接入清单.md”发给她，按模板提供手机可访问的地址、接口文档、真实成功 / 失败样例、鉴权规则，以及图片传输、拍照触发和结果回传方式。
5. 真实图片问药、紧急按钮双击定位通知、硬件播报视觉答案、登录和异地多手机查看尚未完成闭环，不作为本版已验收功能。

七、只想在电脑看页面时

在项目源码根目录，或 ZIP 解压后的根目录打开 PowerShell，运行：

  node scripts/serve-ui-demo.mjs

然后在浏览器打开：

  http://127.0.0.1:4173/

左侧“开发者演示控制台”只用于看页面流程，不属于老人日常界面。模拟录音、拍照问药、紧急按钮和 NextAction 都只是页面演示，不触发真实设备、网络或手机操作。模拟显示 TAP / NO_OP 也不代表手机已经完成点击验证。

联调按“手机权限和文字操作 → BLE ping / pong → 真实 WAV → 后端记录”的顺序进行。视觉图片功能另按双方确认的接口逐段接入。
