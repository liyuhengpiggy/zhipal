语音生活助手 0.6.2 安装与第一次测试

一、把哪一个文件发到手机

1. 安卓安装包：语音生活助手_0.6.2_安卓安装包.apk。
2. 微信传输包：语音生活助手_0.6.2_完整测试版.zip。
3. 电脑微信将 ZIP 发到“文件传输助手”，在手机微信下载；选择“用其他应用打开”，交给手机文件管理器，解压后安装其中的 0.6.2 APK。
4. 如果微信中没有解压选项，在文件管理器的“下载”或“微信”文件夹找到 ZIP，再解压。ZIP 不能直接作为 App 安装。
5. Android 若提示不允许这个文件管理器安装应用，按系统提示允许本次来源安装，返回打开 APK。这是手机系统的安装步骤，软件不能替你确认。

二、覆盖安装，保留资料

1. 手机需 Android 8.0 或更高版本；真实拨号测试需具备可用通话能力。
2. 已安装本项目旧版本，直接覆盖安装，不要先卸载；同签名覆盖通常保留联系人、配置和本机记录。卸载或清除数据会删除本机资料。
3. 这是比赛联调的内部 Debug 测试包，不是应用商店正式发行包。
4. 看到安装器版本与 App 联调报告为 0.6.2，再开始本版测试；不要用旧版包验证“打开 QQ”等新功能。

三、第一次进入：集中准备权限

1. 首次进入本版会显示“第一次使用 · 快速准备”。老人可以请家人先设置一次。
2. 点“开启基础权限”。Android 会按系统规则分别询问，请本人或家人确认：
   - Android 12 及以上：附近的设备，用于连接 ESP32。
   - Android 11 及以下：扫描 BLE 所需的位置权限；旧系统还可能要求开启系统位置信息。
   - 电话：按明确语音指令直接拨打 App 内保存的联系人。
3. 这一步只申请权限，不会立即拨号。不需要逐个向 QQ、微信、抖音申请“允许打开”。
4. 若蓝牙未开，点“开启手机蓝牙”，在系统提示中确认。旧系统若显示位置信息开关关闭，点相应入口到系统设置开启。
5. 已经准备好时点“完成并返回”；也能点“稍后设置，先进入软件”，稍后从“设备与设置”的首次权限引导入口重新打开。
6. 拒绝权限后仍可进入软件；对应功能暂不可用。若系统不再弹出授权框，使用引导中的“到系统设置中管理权限”，在手机系统中自行开启。
7. 硬件 WAV 识别不需要手机麦克风权限，保存联系人不需要读取通讯录；普通打开 App 和拨号也不需要无障碍权限。独立的 NextAction 安全练习另有设置，今天测试这条语音流程无需开启它。
8. 软件不能代点系统“允许”，也没有一次授权就自动开启全部特殊权限的通用开关。双卡手机可由家人在系统里预设默认通话卡，减少日常选卡提示。

四、先不连接硬件，排查手机动作

1. 保持手机解锁，并让语音生活助手在前台。
2. 在“联系人”保存一位测试联系人，例如称呼“女儿”和一个可接听的测试号码。这里保存到 App，不读取手机通讯录。
3. 在“设备与设置”看本机可启动应用数量和状态，再打开原生联调设置，用文字输入测试：
   打开 QQ
   启动微信
   打开抖音
4. 目标软件必须已经安装，名称尽量按手机桌面显示的名字。软件会从本机启动入口查找，无需你逐一登记包名；找不到或同名无法区分会显示原因，不猜着打开。
5. 每打开另一个 App，先返回语音生活助手，再发下一条指令。现在没有后台、锁屏连续控制的保证。
6. 输入“给女儿打电话”。会真实请求系统拨号，不再增加 App 的二次确认；请先用自己的测试号码。称呼必须与保存的一致。系统双卡选择等提示仍可能出现。
7. 打开 QQ 只代表启动 QQ；本版还不能继续在 QQ 内自动发消息或打视频。
8. 文字测试用于确认“找到软件 / 找到联系人 / 请求系统执行”这一段。它通过后再接 WAV，就能把手机操作问题和录音识别问题分开排查。

五、再连接 ESP32，测试真正的硬件语音

1. 在原生设备连接设置填写硬件同学提供的 Service / Notify / Write UUID；若与默认值一致，无需修改。搜索设备并选择自己的 ESP32。
2. 推荐先发送 ping，确认手机能收到并回 pong；它只证明 BLE 消息能互通，不代表 WAV 识别已验收。
3. 硬件直接发完整 WAV 文件的全部字节，从 RIFF 文件头开始，按顺序分 BLE 包发送。推荐 16 kHz、单声道、16 bit 整数 PCM，2–8 秒短录音；无需 JSON 或 Base64。
4. 说“打开 QQ”或“打开抖音”。手机自动执行：
   BLE 收齐 WAV → 本机离线转文字 → 查本机应用名称 → 唯一匹配后请求启动 → 本机保存记录。
5. 说“给女儿打电话”。手机按 App 内保存的号码拨打，无需系统通讯录。
6. 看页面是否依次显示“录音收齐”“手机离线转写完成”、识别文字和动作结果。首次识别需要准备内置模型，请等待，不要连续发送录音。
7. 等上一条处理完，并回到助手前台，再发下一条。识别期间离开助手或断开 / 切换设备，本次转写可保存，但迟到的结果不再执行。
8. 反馈主要是页面文字与手机震动。成功请求操作不代表电话已经接通，也不代表进入目标 App 后已完成其他任务。

六、后端地址先怎么填

1. 暂时没有朋友提供的事件存储完整 URL，就留空。手机仍可识别、打开 App、拨号并保存本机记录。
2. http://192.168.1.17:8000/analyze 是图片分析接口，需要 image 和 intent；不要把 WAV 发给它，也不要把它填进文字记录存储框。
3. 朋友提供事件接口后再配置，记录会异步同步；保存成功的协议见 docs/接口约定.md。
4. 朋友在另一台电脑继续做后端没关系。把 docs/给视觉后端同学的接入清单.md 发给她，按其中模板给 URL、接口文档和真实样例后，我们再接入图片功能。

七、页面中的哪些内容还只是预览

1. 老人首页保留视觉设计，不显示“语音控制”“拍照问药”操作按钮；日常入口来自硬件事件。
2. 真实图片问药、紧急按钮定位通知、账号登录及异地多机查看尚未完成闭环，不作为本版已验收功能。
3. 电脑浏览器中的演示按钮都是模拟，不会读取真机应用列表、拨号、打开 App、上传图片或通知联系人。请用安装后的 Android App 验证真实手机动作。
4. 构建与自动检查最终结果见 docs/0.6.2功能与验证.md；真正的 Android 手机与 ESP32 链路需要按本说明现场逐段验证。
