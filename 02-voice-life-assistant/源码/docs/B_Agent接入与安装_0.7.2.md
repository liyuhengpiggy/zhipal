# B Agent 接入与安装（0.7.2）

## 本次交付

在现有 0.7.1 工程上接入队友 `b_agent_team_handoff.zip` 的 Kotlin 状态机、Android 适配层、Manager / Executor / ActionReflector 和兼容模型客户端。版本为 0.7.2（13），包名不变。

B 的正常流程：手机本地比较截图，页面持续停留（默认 25 秒）→ 弹出“需要我的帮助吗？”→ 按眼镜 B 录音 → 手机离线转文字 → 根据目标提出一个明确按钮点击 → 再次按 B 说“对” → 重新核对页面 → 点击一次 → 比较前后截图 → 显示结果并停止。

“需要”会继续询问目标；“不需要”取消；“不是这个”清除原候选并重新询问目标。只有本次 ACTION 问题、正确 task/prompt、未超时、来源为 B 的明确“对”才进入执行。目标必须唯一、可点击、已启用且有可读标签。拒绝多动作、模糊坐标及敏感按钮。每个询问有效 45 秒（包含 B 录音和识别时间）；分析/执行的宿主超时为 180 秒。

A 录音开始元信息到达手机后，立即清除 B 的弹窗、录音识别、网络请求、待确认操作、截图和旧回调；A 结束也不会恢复旧 B 目标。物理 A 按下到手机收到 BLE 元信息之间仍取决于固件传输。已经交给系统执行的点击无法撤回，A 会阻止后续 B 步骤。

本次保持原来的页面停留触发，未改用队友的“重复点击/页面往返”作为自动触发条件。B Agent 开关默认关闭：关闭时仍走原有 `/vision/analyze` 和 `/analyze` 文字建议流程，不自动点击。

## 手机上怎么设置

1. 安装 `语音生活助手_0.7.2_调试版.apk`。保持手机解锁，连接眼镜；固件必须支持现有 A/B 录音元信息协议。
2. 进入首页设置的“A/B 眼镜帮助”，勾选“启用 B 页面帮助”和“启用 B Agent 单步操作”。
3. 填写队友提供的 **B 模型 API 地址、视觉模型名称、API 令牌**。地址通常是 `https://模型服务域名/v1`，也可填写完整 `/v1/chat/completions`。模型名必须与服务实际提供的 ID 一致；不鉴权的服务可以留空令牌。
4. 保存 A/B 与 Agent 配置。打开系统无障碍里的“语音生活助手 A/B 页面帮助”，返回助手，点击“同意截图分析，开始本次页面观察”。
5. 进入一个无个人信息、无输入框的普通应用页面并停留。收到弹窗后按 B，说例如“我想打开帮助页面”；出现具体点击询问后，再按 B 说“对”。先检查它提出的按钮是否符合目标。
6. 每次停止本次观察、重启应用或断开无障碍后，需要重新同意本次截图分析。修改 A/B 主配置也会结束观察。

B 模型接口与 OCR 服务分别配置。`https://medicine-vision-ocr.onrender.com` 是 OCR 地址；旧 `https://ai-glasses-backend-7bj3.onrender.com` 的图片分析接口也不能直接充当 B 模型接口。交接包没有模型权重或已部署的模型 URL，本版本没有虚构默认模型地址或令牌。

## OCR 局域网配置

调试版在“OCR 服务根地址”填写 `http://192.168.1.17:8001`，勾选“允许局域网 HTTP 联调”，填写实际 OCR Bearer 令牌后保存，先检查模型就绪，再用 JPEG 测试。

手机与运行 OCR 的电脑需在互通的同一局域网；电脑服务需监听 `0.0.0.0:8001`，Windows 防火墙只对所需私有网络允许该端口。地址应以电脑实际 IP 为准。不能把 `127.0.0.1` 当作电脑地址填写到手机上。

B 模型如果也在局域网运行，可单独勾选 B 模型的 HTTP 联调选项，填写该模型实际端口和 `/v1`，不要照搬 OCR 的 8001 端口。

调试版只对显式勾选的内网 IPv4 HTTP 地址放行。正式构建的应用清单禁止明文 HTTP，运行时也拒绝 LAN HTTP，即使偏好中保留了旧调试开关。两个版本的服务 URL、模型名和令牌均来自设置，不写死。

## 后端同学需要提供什么

已有 OCR 与原视觉 Render 服务无需为了这次 B 接入更改接口。B 需要另外提供可供手机访问的视觉语言模型服务：

- OpenAI 兼容 `POST /v1/chat/completions`，接收 `model`、`messages`，其中 user.content 包含 `image_url`（JPEG base64 data URL）和 `text`；返回 `choices[0].message.content` 字符串。
- 视觉模型必须能按提示返回规划、单步动作和前后图反思的文本格式。每次正常任务会进行规划、候选操作、执行后检查三类模型请求；模型准确率需要用真实手机页面验证。
- 返回实际 API 基址、model ID、是否需要 Bearer 令牌；若服务经代理，需要确保代理保留图片输入和原始响应内容。
- 手机客户端不跟随 HTTP 重定向，因此应填写最终 API 地址。正式版需要有效 HTTPS。

不需要把模型权重打入 APK，也没有将队友的示例 APK 当作主程序替换。详细来源和原始接口文档在 `docs/b-agent-upstream/`。

## 固件兼容

沿用 0.7.0 的 A/B 协议，手机发出 `assist_prompt`，含 `prompt_id`、`task_id: b-<prompt_id>` 和 `question`。固件每次 B 录音必须绑定最新的这组值，并使用 `source_button: B`、`purpose: assist_reply`、正确 `session_id`、唯一 event ID，再发送完整 WAV。需求问题与操作确认是不同的 prompt，不能复用上一次的值。

Agent 内部 task ID 与 BLE task ID 在手机端绑定，不需要固件识别 Agent 内部 ID。收到 `assist_cancel` 应丢弃对应旧询问；A 开始必须立即发 `recording_meta` 或 `button_start`，不能等录音传完才通知。执行结果可收到 `result`，status 为 `assist_step_result`。原有 WAV 格式、分块、重复包校验不变。

## 边界与验收

支持一次明确点击及执行后检查；不提供连续代办、输入、滚动或完整视频通话流程。支付、转账、发送、删除、授权等动作需要用户手动完成。锁屏、密码、敏感应用、可见输入框、多窗口和含个人信息的页面沿用原有拦截。动态页面可能无法通过前后页面一致性校验，此时停止，不猜测点击。

Android 无障碍截图要求系统提供 Android 11 / API 30 以上接口。HarmonyOS 名称与内核版本不能单独证明该接口支持，仍需在 Mate30 真机验证。

电脑侧构建、JVM 回归、静态检查和 APK 清单/签名校验记录见 `0.7.2功能与验证.md`。目前没有连接手机或 ESP32，也没有可用的 B 模型配置，不能把本地测试当作真机全链路或真实模型识别通过。
