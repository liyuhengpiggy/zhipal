# 0.7.7：App → 服务器 → 手机反馈

本版保留 A/B 原有功能和 0.7.6 OCR 结果弹窗，新增独立的真实服务器通路测试页。先验证手机选图后能获得真实服务器结果，再做硬件录音、眼镜拍照和 B 点击联调。测试页不操作手机，不冒充真实眼镜拍照或当前页面采集。

## 手机怎么测

覆盖安装 `语音生活助手_0.7.7_调试版.apk`，不要卸载旧版，以保留地址和令牌。

进入首页的“A/B 眼镜帮助 · 配置与状态”，先保存 OCR、原视觉服务、B 自建代理各自的地址和令牌；然后点顶部“服务器通路测试（选图 → 服务器 → 手机结果）”。

1. OCR：选清晰药盒 JPEG，问题填“生产日期是什么？”，点“单独测试 OCR”。页面显示就绪检查、创建任务、上传和轮询进度；结束后弹窗显示真实答案、识别原文和候选复核提示，或失败原因。
2. A 视觉：选实物或普通页面 JPEG，填写相关问题，点“单独测试 A 视觉”。发送到原视觉服务的 `/analyze`，检查有效 message；`action:unknown` 明确算未通过。
3. B 页面分析：选不含个人信息的手机页面 JPEG，点“单独测试 B 页面分析”。发送到原视觉服务的 `/vision/analyze`；必须为 `status:ok`、`mode:cloud` 且有场景文字。mock 不算通过。
4. B Agent：选普通手机页面 JPEG，点“单独测试 B Agent”。真实 JPEG 经 Base64 送自建代理，再由模型返回计划。复用正式模型客户端及 Thought/Plan 解析器；仅验证图像输入、推理返回和计划解析，不执行操作，也不验证真实控件绑定、点击确认或操作后检查。

“测试全部已配置通路”依次尝试四条路线；未配置的路线明确显示未通过，其他路线继续。不同路线最好分别换对应图片。选图不会自动上传，点击测试才发送。结果显示在本页和结束弹窗中；本页联调结果未加入历史记录，不进行语音播报。选图最多 8 MiB / 1600 万像素；原视觉服务两条路线另限 2 MiB。测试暂停 B 观察并结束旧 A/B；离开页面或新 A/B 任务改变会取消并丢弃旧结果。测试结束后需要手动重新开始 B 页面观察。

OCR 的 `not_found`、`unsupported` 和多个候选均保留真实类型；“请求与解析通过”仅说明通路正常，不表示生产日期一定识别正确，必须核对原图。

## 给后端同学的当前处理指令

1. 原视觉服务器：检查实际部署配置与日志，恢复真实视觉模型调用；`/vision/analyze` 必须返回真实 `status:ok / mode:cloud / analysis`，不能保持 mock。`/analyze` 要支持 image+intent 的图片问答并返回有效 message，不能仅保留 open_app/unknown 的命令路由。环境变量名以该后端实际代码为准，不凭空指定。
2. OCR：检查 Render 部署是否 Live、端口绑定、模型启动、依赖和内存；保证 `/health` 在手机网络可访问，并返回 `ready:true`、`capabilities.ocr:true`。交付 `VISION_API_TOKEN`，在手机 OCR 设置中填写。再使用 JPEG 验收创建、上传和轮询终态，不以 health 正常代替识别测试。具体协议继续使用 `docs/发给后端同学_Render部署指令.md`。
3. B：部署项目 `b_agent_proxy/`。Node 22，Build `npm install --ignore-scripts`，Start `npm start`，Health `/healthz`；服务端配 `SILICONFLOW_API_KEY` 和独立至少 32 字符的 `B_PROXY_TOKEN`。交付实际 HTTPS 地址加 `/v1` 和 B_PROXY_TOKEN，手机模型名填 `Qwen/Qwen3-VL-8B-Instruct`。提供商密钥只放服务端，不写 APK。

## 完整产品验收仍需完成

打开应用、联系人拨号、离线 Vosk 识别属于本地功能，不强制绕服务器。记录同步后端也独立于三类模型服务，本页不测试历史记录上传。

服务器通路通过后，再验证 A 硬件输入（v1/en 文字或原 WAV）→正确路由→本次眼镜 JPEG 上传→OCR 返回→手机结果弹窗；B 则验证真实同页停留→帮助询问→B 录音→模型建议→本次用户确认→一次点击→结果检查。同时测试 A 抢占后 B 的旧弹窗和迟到结果不会执行。

不能把本页 B 计划解析通过称为“B 全流程完成”，也不能把电脑 HTTP 通过称为“手机实测完成”。
