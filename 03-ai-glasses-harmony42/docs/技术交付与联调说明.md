# AI 眼镜前端、后端、硬件、云端合龙技术交付说明

版本：0.1.0；日期：2026-10-25（北京时间）。用途：团队联调原型，不是医疗器械或安全导航产品。

## 1. 交付边界与现状

本次新增独立 Android 手机客户端源码，不替换原网页，不改变原有后端/固件协议，不修改药品 OCR fields，不在后端或手机加入镜像翻转。
摄像头方向由硬件同学处理。视觉增强只用于原网页预览，识别提交的是原图。

| 项目 | 状态及验收边界 |
| --- | --- |
| 云端照片后端、网页、WSS 接收 | 已有功能；此前在线收到真实硬件照片，不等于本次手机验收 |
| 多功能助手后端 | 已部署：读文字、认物、场景；有访问保护 |
| 独立 OCR | 原服务保留，通用文字与药品结构字段并存 |
| Android 客户端 | 本次新增源码；包含原图预览、配置检查、识别、OCR 查询、系统 TTS |
| 手机安装/中文播报/端到端效果 | 需实际 APK 构建和目标手机验收，不能用后端单元测试替代 |
| 蓝牙事件、硬件按键、手机控制拍照 | 未实现；没有提供现有固件源码和消息协议 |
| 手机自动点击/导航/避障/语音唤醒 | 未实现，当前权限和工程中不包含这些能力 |

本次没有上传或修改生产服务。历史发布的照片后端提交为 `a9f294f`；交付的是当前本地代码快照，不应把它直接当作云端精确提交镜像。

## 2. 系统架构与责任分工

```text
眼镜摄像头（方向、曝光、JPEG、Wi-Fi、重连由固件负责）
  │ WSS：每个二进制消息 = 8字节协议头 + 完整 JPEG
  ▼
照片后端 ai-glasses-backend-7bj3.onrender.com
  ├─ 最新原图内存缓存 → 手机原图预览 / 原网页增强预览
  └─ 点击识别：/api/v1/assistant/analyze
       ├─ read_text → medicine-vision-ocr.onrender.com → OCR 任务轮询
       └─ objects / scene → 已配置云视觉模型 → 同步返回答案
  ▲
  │ HTTPS，Bearer 网站访问令牌；OCR 可使用独立令牌
Android 手机客户端 → 显示答案 / 用户选择中文 TTS 播报
```

手机不直接接收摄像头视频，也不充当上传网关；采用现有“硬件直传云端”最小改动方案。
两端都需要联网。不是脱网识别，不要求同一个 Wi-Fi；若硬件只支持手机热点，由硬件同学配置热点凭据和断线重连。
APK 不自带 Python、OCR 权重或厂商云模型 Key。手机仅使用 HTTPS 和系统语音引擎。

前端同学：维护 Android UI、生命周期、任务状态、TTS、异常交互和真机适配。
后端同学：维护助手/原接口、原图一致性、令牌鉴权、请求超时和云模型适配。
硬件同学：负责相机方向、清晰度、按键与固件、上传顺序和 WSS 重连。
云端管理员：负责部署、环境变量、服务可用性、配额、数据留存和密钥轮换。

## 3. 手机构建与 HarmonyOS 兼容性

本项目生成 Android APK，不是 HarmonyOS NEXT 原生 `.hap`。只有具备 Android APK 兼容能力的目标手机才能安装。
需提供确切手机型号、完整系统构建号以及是否允许安装外部 APK，再执行真机验收；不能仅凭 HarmonyOS 4.2.0 字样保证兼容。

工具链：JDK 17、Gradle 8.9、Android Gradle Plugin 8.7.3、compile/target SDK 35、min SDK 26、Build Tools 35.0.0。
Android Studio 导入 `mobile-android/` 并选择本地 Gradle 8.9，或配置命令行环境后运行：

```powershell
cd mobile-android
gradle --no-daemon :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

调试包路径：`app/build/outputs/apk/debug/app-debug.apk`。调试签名只适合联调；正式 APK 需团队生成和保管发行签名。
本包无 Gradle wrapper 二进制，可使用项目自带 `BUILD_APK.ps1` 调用已安装的 Gradle。
可选 CI 工作流只作为模板，尚未上传或执行；不得为构建把密钥提交到仓库。

权限只有 INTERNET，不申请相机、麦克风、蓝牙、存储或无障碍服务。窗口启用截图保护，部分手机会禁止截屏/投屏。
target SDK 35 的系统栏、字体放大、前后台切换需真机检查；App 无原生 ABI 依赖，但这不等于已验证所有设备。

## 4. 硬件协议（保持不变）

地址：`wss://ai-glasses-backend-7bj3.onrender.com/ws/camera/upload`。
每帧发送一个二进制 WebSocket 消息，不等待逐帧 ACK：

| 偏移 | 类型 | 内容 |
| --- | --- | --- |
| 0–3 | uint32 little endian | 数值 `0x4B564630`，实际字节 `30 46 56 4B` |
| 4–7 | uint32 little endian | 连接内递增 seq |
| 8 以后 | bytes | 完整 JPEG（含首尾标记），总图像不超过 10 MiB |

不要把魔数字符串误写成 `KVF0`。固件重连后可从 0/1 开始；同连接内不得归零。
最新有效上传连接接管全局画面，旧连接不能抢回。不要并行开启另一个测试上传端，否则可能覆盖真实画面。
保持 latest-only，不在设备端排积大量旧图；接收端不自动调用模型。详细说明见 `backend/WSS_CAMERA_DEPLOY.md`。
备用 HTTP 上传仍是 `POST /camera/frame`，multipart 字段 `file`；`/upload` 有临时落盘，不能混为实时识别。

## 5. 手机调用接口

固定后端：`https://ai-glasses-backend-7bj3.onrender.com`。当前客户端不提供任意地址输入，防止误发访问令牌。

| 接口 | 用途 | 鉴权 |
| --- | --- | --- |
| GET /health | 进程健康，不代表模型可用 | 无 |
| GET /camera/performance | WS 连接、接收 FPS、累计帧数 | 当前原型无 |
| GET /camera/latest | 最新原图；无图 204；可能是缓存旧帧 | 当前原型无 |
| GET /api/v1/assistant/capabilities | 检查云视觉 Key / 服务端 OCR token 是否配置 | 网站 Bearer |
| POST /api/v1/assistant/analyze | 触发三种模式之一 | 网站 Bearer；OCR 可附 X-OCR-Token |
| GET /api/v1/assistant/ocr/{task_id} | 查询本助手 OCR 任务 | 同上 |

请求示例（占位符不是可用凭证）：

```http
POST /api/v1/assistant/analyze
Authorization: Bearer <VISION_API_TOKEN>
X-OCR-Token: <OCR_SERVICE_TOKEN>
Content-Type: application/json

{"mode":"read_text"}
```

`mode` 仅允许 `read_text`、`objects`、`scene`，不允许 `mirror` 等额外字段。
后端只取 5 秒内最新帧；无画面/过期返回 409；OCR 只接受 JPEG；助手图片上限 8 MiB。
预览可以显示最后一帧，但这不证明画面仍在更新；需结合累计帧数/FPS/连接状态判断。
后端返回 frame.sequence/source/received_at 及两个 SHA256；原图与提交 SHA256 应一致。

认物/场景响应的 `answer` 用于显示及播报，`review_required` 只是核查提示，不是准确率。
OCR 提交返回 `task_id: assistant-<32hex>` 与 `ocr` 快照；状态轮询间隔 2 秒，终态为 succeeded/failed/timed_out。
OCR `answer` / `evidence_text` 用于读文字；`result.fields` 仍保留原结构，不删除或重新解释药品字段。
完整 JSON 显示在手机上，TTS 只读 answer，不把原始 fields 当作已确认的用药结论。

错误：401 检查访问凭证；409 先恢复实时传图；413 缩小硬件单帧；415 确认 JPEG；422 检查请求和 OCR token；
429 等待已有提交；502/503 检查上游/配置；504 超时先查已知 OCR 任务，不自动重新提交。
停止等待只影响本机轮询和播报，不能撤回已发出的网络调用或取消云端任务/费用。
单次网络读超时最长 145 秒；OCR 轮询预算 180 秒，不是严格的总请求截止时间。

## 6. 云端配置与秘密管理

照片后端保持现有 `python -m app`、单 worker 和原有 AI_* / VISION_* 配置，不为手机端改动旧配置。
新助手依赖：

| 环境变量 | 用途 |
| --- | --- |
| VISION_API_TOKEN | 网站 Agent 令牌，客户端第一栏使用 |
| VISION_QWEN_API_KEY | 云模型供应商 Key，只在服务器设置 |
| VISION_QWEN_BASE_URL | 当前认物/场景供应商 API 地址 |
| VISION_QWEN_MODEL | 供应商实际支持的视觉模型 ID |
| ASSISTANT_OCR_BASE_URL | 默认独立 OCR 的 HTTPS 域名 |
| ASSISTANT_OCR_TOKEN | 可选；让后端保管 OCR 令牌，手机无需另填 |

独立 OCR 的 `VISION_API_TOKEN` 是它自己的令牌，和照片后端同名变量不是同一作用域。
腾讯云 OCR 凭据按 `docs/OCR云端配置.md` 设置在独立服务，不进入手机和照片后端。
本包不含 `.env`、测试令牌、云 Key、生产数据库、照片、模型权重或发行签名。
客户端令牌只在内存保存，不调用 SharedPreferences；退出/重建后需重填，避免把共用令牌嵌入 APK。

重要生产缺口：当前摄像头读取和上传没有按用户/设备隔离，公开域名访问者可能看见同一画面。
助手 Bearer 保护不等于整个摄像头系统已受保护。正式用户使用前必须增加用户鉴权、设备绑定、私有画面访问、
限流、审计、配额、服务商数据留存核查和任务持久化，不能直接扩大为公开多用户产品。
Render 重启会清空照片后端内存；OCR 数据依赖独立服务存储策略，须确认其磁盘和保留规则。
原型不自动将结果作为指令执行，不开放自动转账/发消息/删数据能力。

## 7. 四端联调验收表

以下均需记录手机型号、App 版本、服务器版本、时间和实际观察，不可预填“通过”。

| 用例 | 操作 | 合格标准 |
| --- | --- | --- |
| 安装启动 | 在目标 HarmonyOS 4.2 手机安装 APK | 可打开，无崩溃、无不必要权限 |
| 硬件收帧 | 眼镜对着可移动目标，检查累计帧 | 数值递增，画面方向正确，说明仅固件镜像 |
| 手机预览 | 开始原图预览，移动目标 | 能看到对应变化；不是把最后缓存帧当实时 |
| 助手鉴权 | 正确/错误网站令牌分别检查 | 正确可查配置，错误返回 401，不反复重试 |
| 中文 OCR | 拍清楚大字标签后读文字 | answer 与原图人工比对；记录漏字/误字，不只检查 HTTP 200 |
| 药品兼容 | 拍药盒并查询 OCR | 原 fields 结构保持，信息不确定有提示，不给服药建议 |
| 认物 | 杯子等常见物体，点击识别 | 有真实模型 answer，和原图核对，不把 mock 当成功 |
| 场景 | 室内场景，点击描述 | 可见物体和位置合理，无无法证明的安全保证 |
| 中文播报 | 安装/启用系统中文 TTS 后勾选 | 可听见答案；无引擎时明确提示，文字仍可用 |
| 后台/停止 | 识别中按停止或切到后台 | 不再发起后续轮询/播报，无自动重复付费提交 |
| 断网/冷启动 | 手机断网或 Render 冷启动 | 错误/等待可见，不生成虚假结果，可手动重试 |
| 旧功能回归 | 使用原网页/原上传/旧分析接口 | 协议与旧行为保留，手机不创建假帧抢占硬件 |

建议以 10 张文字、10 张物体、5 个场景记录成功率、OCR 字错误、首帧和识别延迟、流量和费用。
自动化后端测试只能证明接口约定和受控异常，不证明模型准确率、APK 能安装或手机能播报。

## 8. 后续硬件按键对接（建议，未实现协议）

当前最小闭环：眼镜持续上传 → 手机按钮取云端最新帧 → 识别 → 手机播报。
要实现“眼镜按键即识别”，必须先由硬件团队确认蓝牙/串口/Wi-Fi 事件协议、配对和身份认证、按键去抖、
拍照请求与完成事件、任务标识、照片关联及断线重试。不能把当前 WSS 图片头误当按键协议。
建议按键事件携带唯一 event_id，手机去重后创建任务，固件返回同一 task_id 对应照片；目前助手只选最新全局帧，
不支持指定某次硬件拍照或按键照片，因此严格任务关联还需要后端/固件共同扩展，不能仅加按钮宣称完成。
眼镜喇叭播放也要确认音频通道；当前 TTS 出声位置由手机系统音频路由决定，不保证眼镜播放。

## 9. 交付目录与复现

`mobile-android/`：新增手机源码、构建入口、CI 模板和 README。
